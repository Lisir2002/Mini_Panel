# Mini Panel 功能设计

> 本文件是**功能范围的决策记录**：模块怎么切、页面有哪些、每个功能点要占哪个能力位图 key、
> 走哪些接口、落在哪个里程碑，以及明确不做什么。
>
> 它与仓库其他文档的分工是：`技术选型与MVP规格.md` 管**怎么做**（栈、约束、纪律），
> `里程碑.md` 管**什么时候算做完**（验收），本文件管**做什么、不做什么**。
>
> **措辞约定**：本文点名竞品时，只写**可从其公开文档、公开前端资产或本机界面上直接观察到的行为**，
> 不引用闭源产品的源码内部路径、行号或代码片段，也不引用只在内部调研档案里存在的取证细节
> （那些档案不进仓库）。开源项目（1Panel / Cockpit / Webmin-Virtualmin / CloudPanel / Portainer /
> HestiaCP / pfSense / OPNsense / RouterOS / LuCI）一律按公开出处引用。
> 凡写"参照系里只有某项目做到"，后面必须能给出该项目的公开出处，否则降级为"我们的判断"。
>
> **落地的唯一顺序**（继承 `技术选型与MVP规格.md` §8.2）：先有跨平台实现与路由 → 再改
> `internal/platform/capabilities_test.go` 的白名单 → 最后才改本文与 `里程碑.md`。
> 反过来写就是超前承诺。所以本文里所有里程碑调整都是**待执行的改动清单**（§10），不是既成事实。

## §1 六条立场

后面每一节的取舍都从这六条推出来。这六条不是愿望，是**已经在代码里或即将在代码里的约束**。

**1.1 界面唯一的渲染依据是服务端能力位图，位图从"能不能"升级为"处于什么状态"。**
参照系里没有人把能力位图做成对用户可见的一等公民：最接近的三种做法是模块清单里的
`os_support` 声明、`virtualmin list-features` 这种可查询接口，以及 Cockpit 的"整块隐藏 + 降级 +
给一个补齐前置的按钮"。1Panel 的引擎层已经按后端拆了能力接口并定义了
`ErrAdapterUnavailable / ErrInventoryUnavailable / ErrFamilyUnavailable`，但文档仍然要求用户
"自己去装 firewalld" —— 引擎能力化了，UI 没能力化。我们两步一起做（§4）。

**1.2 面板只承诺管理"自己创建的对象"；其余一律可见但只读，并标出真实来源。**
这条决定了很多页面的形状。它同时解决两个参照系里都存在的问题：接管别人写的配置会导致状态
不可控（1Panel 的 Compose 只允许编辑自己部署的，Hestia 的 `system` 套餐不可改），而只显示
"我加的规则"的防火墙列表则在骗人（Docker `-p`、k8s NodePort 就是主机版 UPnP，会绕着面板改内核
规则；pfSense 对 UPnP 动态规则的做法是"让它可见、可辨认"，不是假装不存在）。

**1.3 写操作是三段式：预检 → 快照 → 执行并回报影响清单。"可回滚"是功能，不是提示文案。**
路由器面板在这点上比服务器面板成熟：pfSense 的配置历史明写每条记录含改动人、来源 IP 与修订号，
改坏了有四层出路。我们的审计已经记 actor/IP/time/`params_hash`，但记的是**事件**而不是**状态快照**
—— 这是当前最大的自救缺口。因此快照不打算等 M6，而是作为写协议的一部分从 M2 起就存在（§5）。

**1.4 每个能把用户关在外面的开关，必须有一条对称的 SSH 侧解锁命令。**
参照系里这是共同底线：`1pctl reset entrance/ips/mfa/https/domain`、CloudPanel 的 CLI 关 2FA、
Portainer 的 `reset-admin`、Hestia 的 `v-change-*`；Cockpit 干脆不建自己的账号体系来规避。
我们现有 `init / doctor / passwd / reset-entrance` 四条，逐条核对后有**两个"能把自己锁死却没有
出路"的缺口**（IP 白名单、2FA）和**一条"设置项可写但无执行点"的虚假安全感**（口令有效期），
见 §6.3。G-A / G-C 是本文新增到 M1 的两条（§10 A1）；G-B 的条目本来就在 M1
（`docs/里程碑.md` 的 M1 表里「口令有效期真正生效」那一行），这里做的只是把它从"前端换代时顺带做"提到"第一件事"。三条都排在
任何新页面之前。

**1.5 暴露面是这类面板的主语，而不是防火墙页的一个子功能。**
"我从外面看得见吗"和"面板开在哪张脸上"是两个问题，M0 只回答了后者的机制部分。
所以概览页必须回答三张脸（公网 IP / 内网 IP / 回环）+ 谁在监听 + 现在有哪些连接，
而这三项的成本只是读 `ss` 和一次真实解析（§3.1、§3.5）。

**1.6 范围靠"负担档"守，不靠"必备档"堆。**
参照系里最能说明膨胀代价的是 Webmin 的 127 个模块目录（`adsl-client`、`minecraft`、`sgiexports`
至今仍在，每一个都是 CVE 面）和它官方列出的提权/SSRF 公告清单；1Panel 则把 AI 网关整块塞进
v2、同时把 WAF/uptime/多节点划进付费档。**"面板里可传任意参数的命令执行器"和"可下任意 URL 的
下载器"是提权入口，不是功能**（参照：终端能做同样的事，差别在于终端在登录控制和审计里可见）。
§8 的不做清单比 §3 的页面清单更重要。

## §2 模块划分

10 个一级模块。导航顺序 = 用户排查一台陌生服务器时的动手顺序。

| # | 模块 | 路由 | 它回答的问题 | 明确不在这里的东西 |
| --- | --- | --- | --- | --- |
| 1 | 概览 | `/overview` | 这台机器现在什么状态、我从哪张脸能看到它、有没有正在烧的东西 | 任何写操作（概览只读，按钮一律跳到归属模块） |
| 2 | 网站 | `/site/*` | 有哪些站点、每个站怎么被服务、证书什么时候到期、PHP 版本与扩展 | 容器；应用商店；站点级 WAF |
| 3 | 数据库 | `/database/*` | 有哪些实例/库/账号、能从哪里连、慢在哪 | phpMyAdmin 内嵌反代（§8） |
| 4 | 文件 | `/file` | 看/改/传文件与属主权限 | 回收站、文件历史、免登录分享（§8） |
| 5 | 安全 | `/security/*` | 内核放行了什么、谁写的、命中没有、面板自己被保护成什么样 | 签名库扫描；fail2ban 全 jail 可视化 |
| 6 | 监控与服务 | `/monitor/*`、`/service/*` | 指标历史、逐连接、systemd 单元与进程 | GPU/AI 维度；多主机聚合 |
| 7 | 终端 | `/terminal` | 改坏了要能进系统自修 | 远端主机凭据保管与多主机批量输入（§9） |
| 8 | 任务 | `/task/*` | 计划任务、备份、配置版本与回滚 | 亚秒自建循环冒充 crontab（§8） |
| 9 | 日志与审计 | `/log/*` | 谁动了什么、按对象聚合的时间线 | 可被面板清空的审计（永不做，§8） |
| 10 | 设置 | `/config/*` | 面板自身访问控制、账号与 2FA、会话、告警、能力矩阵 | 主题/水印/logo |

模块与现有位图 key 的对应关系：`site` / `php` / `php_ext_source` / `ssl` 归 2；`database` 归 3；
`file_posix_perms`（+ 提案 `file_manager`）归 4；`firewall` / `firewall_write`（+ 提案 `listeners`
`connections`）归 5 与 6；`monitor`（+ 提案 `service`）归 6；`terminal` 归 7；`cron` / `backup`
（+ 提案 `config_history`）归 8；`audit` 归 9；面板自身安全在 10（M0 已交付，不占新 key）。

## §3 页面清单 × 能力 key × 里程碑

状态词表：`已交付` = 代码与测试都在；`M1`…`M6` = 计划内；`M4 后` / `未排期` = 未进里程碑；
`不做` = §8 明确拒绝；`提案` = 本文新提的 key 或接口，尚未进代码。

### §3.1 概览 `/overview`

| 页面/区块 | 功能点 | 能力 key | 里程碑 | 备注 |
| --- | --- | --- | --- | --- |
| 概览 | 主机身份（发行版、内核、架构、运行时长、面板版本） | `monitor`（读侧） | 已交付 | `GET /api/v1/system/info` |

### §3.5 安全 `/security/*`

| 页面 | 功能点 | 能力 key | 里程碑 | 备注 |

## §4 能力位图契约 v2（提案）

### §4.1 从 bool 到四态

提案的起点是 v1：`features[key] = bool`，`false` 时另有一个 `unavailable[key]` map 装理由。
这个 bool 已经比参照系好（它只能表达"能 / 不能"），但实际状态有四种，混在一个 bool 里就会
重新产生"点了才知道失败"。下面这张形状是 M1 落地的东西，不是待办：
`Feature{State, Reason, FixAction, Verify}`（`internal/platform/capabilities.go:121`），
`Features map[string]Feature`（`internal/platform/capabilities.go:163`）。v1 那个和 `features`
可以各说各话的平行 map 已经删掉，规格里写着这条删除（`internal/api/openapi/panel.yaml:160-162`），
页面上也没有它的位置（`web/src/views/CapabilitiesView.vue:38 featRow()` 只读 `features[key].state`）。

```jsonc
"capabilities": {
  "features": {
    "firewall_write": {
      "state": "degraded",                 // available | degraded | unavailable | foreign
      "reason": "ufw 后端可用，但 iptables 规则表里有 4 条不是面板写入的，面板不会改写它们",
      "fix_action": null,                   // 可执行的一步（幂等、有界）；没有就 null
      "verify": "GET /api/v1/security/firewall/rules?source=foreign"  // 用户如何自己确认
    }
  }
}
```

| state | 语义 | UI 表现（三选一，不允许第四种） |
| --- | --- | --- |
| `available` | 本版本、本机、此刻真能做 | 正常控件 |
| `degraded` | 主路径可用，某一支不可用或缺前置 | 控件可用 + 顶部一条"能用但少了 X"；缺前置且我们能补时给 `fix_action` 按钮 |
| `unavailable` | 这一版没做，或本机条件不成立 | **不隐藏**：禁用控件 + 一句原因 +（若适用）一个补齐前置动作或里程碑编号。只有与本机无关的模块才整块收起 |
| `foreign` | 对象存在但不归面板管 | 只读呈现 + 原因（"由 Docker 写入"/"非面板创建的 vhost"） |

迁移成本（已付）：`features` 与 `unavailable` 两个 map 合成一个是破坏性变更，四处必须同改——
`openapi/panel.yaml`、`internal/api/handleCapabilities`、`webui/dist` 消费点与
`capabilities_test.go`，漏一处就出现"接口说一套、页面画一套"。四处同改由
`TestCapabilitiesAreSelfConsistent`、`make check-contract` 与 `make check-ui`（能力 key 全覆盖那条）
分别把住。**收益**：1.1、1.2 两条立场第一次变成机器可读。

### §4.2 `fix_action` 的边界（这条最容易写坏）

"一键补齐前置"如果实现成"面板去装包"，就同时违反不装第三方代码与不引入长尾依赖两条纪律。
所以 `fix_action` 只允许三类：
① 面板自己有权限做的动作（如打开监控采样、生成自签证书）；
② 输出**可直接复制的命令**并留一行"执行完点这里复查"（把参照系里"你自己去装"变成"给你确切
一条命令 + 事后能验证"）；
③ 指向 `verify` 的只读复查。
禁止：`fix_action` 承载任意包名/任意 URL/任意命令。

落地进度与一处口径差：本文 ② 允许"一条可复制的命令"，而
`internal/api/openapi/panel.yaml:592-594` 对这个字段的说明写的是"不允许包名"——两处取严的那个，
所以 M2 第一处生产代码里的 `Degrade()` 调用（`internal/platform/platform_linux.go:564`）
把 `fix_action` 留空。缺的是什么写在 `reason` 里（那是给人读的一句说明，不是这个字段的载荷），
`verify` 走 ③ 的两条只读复查路径。`TestDoctorPHPRootedHostNamesTheVersion` 把这三件事钉住：
`fix_action` 必须为空、`reason` 必须点名探测到的版本、`verify` 必须同时含 `doctor` 与 `capabilities`。
要放开 ② 就得先改 `panel.yaml` 的这段描述并说明命令模板从哪来，不能在实现里先斩后奏。

### §4.3 key 命名与新增审批

新增 key 必须同时给出：语义、读/写、跨 Linux/Windows 的实现路径、`state` 由什么决定、
被哪条测试钉住。**本文提出的新 key 全是提案**，未进代码：
`listeners`、`connections`、`net_view`、`dns_view`、`file_manager`、`database_write`、
`service`、`log_view`、`config_history`、`notifications`。
`vpn` 不进提案（未排期，§9）。
顺序纪律：实现与路由 → 改 `capabilities_test.go:179` 白名单 → 改文档 → `make check-docs`（文档里的
`文件:行` 与点名的测试名由 `internal/docsync` 机检，指针漂了就红）。

### §4.4 路径参数纪律（这条挡住了新页面的设计自由度，写清楚）

`internal/api/contract_test.go:92-106` 目前只允许 `{key}` 一种路径参数，写死是为了拒绝
"名字 → 代码"的反射式分发。§3 里出现了站点、库、任务的资源标识，因此需要放宽，但只放宽**身份**：

- 允许：`{id}`、`{name}` 这类**只用于取标识**的参数，服务端强校验字符集与长度，且必须能在
  handler 里映射到一次数据库主键查询。
- 仍禁止：任何动词性/模块性参数（`{action}`、`{module}`、`{fun}`、`{cmd}`）。
- **内容选择器不进 URL**：文件路径、日志文件、任务脚本一律放请求体或查询串并各自校验，
  绝不出现 `{path}`。这条决定是文件管理器不变成遍历器的关键。

契约测试相应改为：路径参数白名单 `{key, id, name}` + 反射特征黑名单不变。

## §5 跨模块的三条写协议

这三条不属于任何单个页面，是 M2 起所有写端点共用的形状。

### §5.1 预检先于执行

每个写端点在执行前先返回一份检查结论（`{ok, checks[], blocking[]}`），不足就拒绝执行并给
**分条解法文案**。参照系里被记录的廉价预检：备份前空间 ≥ 2× 估算、存储账号先试传一个文件、
端口占用先查 `ss`、签发证书前确认 DNS 记录已生效、资源门限不满足就不开始重活。
M2 最小集：Nginx 配置语法（`nginx -t`）、端口冲突、根目录存在与可写。

### §5.2 快照先行 + 影响清单

规则：**任何跨子系统写入前，面板自己必须已经能撤回**。

- 落地形态：`<data>/config-history/<对象>/<时间戳>` 存改前字节 + 元数据（actor、来源请求、
  `params_hash`）；回滚是写操作，因此自己也要留快照（不允许"回滚的回滚"死循环：快照链有深度上限）。
- 响应形状：写成功后返回 `{affected: {files: [], units: [], ports: [], reload: bool}}`，
  同时进审计。用户应该看得到"这次动了哪些文件/端口/服务"，而不是自己去 `diff`。
- 各模块首个必须遵守的时点：M2 Nginx 配置、M2 PHP 配置文件、M3 实例配置（若开放写）、
  M4 防火墙规则（`internal/platform/paths.go:44-53` 已把 `Snapshot()/Restore()` 定成接口强制成员）、
  M6 crontab（写系统 crontab 前留备份）。
- **因此 `config_history` 的"能力"在 M2 就有，UI 页在 M4**。把它整块排到 M6 是错的：M4 一上线，
  改错一条防火墙规则就足以把人关在门外，而那天离 M6 还很远。

### §5.3 对象归属（`foreign`）

每个 Provider 读回来的对象必须带来源标记，UI 据此决定按钮形态。归属规则由数据源决定，不由
面板意愿决定：

| 对象 | 面板可写 | 只读（foreign）来源举例 |
| --- | --- | --- |
| vhost / Nginx include | 面板创建的站点 | 发行版默认站点、手工写的 conf、Certbot 改过的行 |
| 防火墙规则 | 面板写入的按注释/链标记 | `DOCKER`/`KUBE-` 链、云厂商 agent、`fail2ban-*` 链 |
| systemd 单元 | 面板生成的 unit 文件 | 包自带的 unit |
| crontab | 面板任务落独立 include 目录 | 系统 `/etc/cron.d/*`、用户手工 `crontab -e` 的行 |
| 数据库 | 面板建的库/账号 | 外部应用自建 |

配套纪律：面板**不接管**已存在的同名对象（创建时冲突就报错并指出来源），也不做"同步认领"。
这条比"支持更多场景"更能避免状态漂移，也顺带回答了"为什么列表里没有我手工加的那条规则"——
它在，但是灰的，理由写在 `reason` 里。

### §5.4 ACME HTTP-01 的边界与流程（M2 第五片落地）

这一节只描述**已交付**的那条路径。选择 HTTP-01 而不是 DNS-01 的理由是：面板必须能在
"只有一张 A 记录、没有 DNS API 凭据"的机器上工作，而 DNS-01 会把凭据保管、域名商 API、
传播延迟三件事一起拖进来。代价必须写在明处：**通配符证书签不了**，只能手工上传。

签发的固定顺序（写代码时按这个顺序，不要交换）：

1. **先改配置再签发**。`PrepareACME` 确保 80 端口块里有
   `location ^~ /.well-known/acme-challenge/`，且它排在 `return 301` 之前；旧版本写出的
   redirect 配置在这里升级。仍然是写配置 → `nginx -t` → 通过才 reload，失败回滚。
2. **账号密钥复用**。`/etc/minipanel/acme/account.key` 是 ECDSA P-256，首次创建 0600、
   父目录 0700；已存在就加载，`Register` 遇到 `ErrAccountAlreadyExists` 视为成功。
   没有这一步，第二次签发/续期会被 ACME 服务端拒绝——Pebble 集成用例连跑两次就是为了钉它。
3. **challenge 写进站点自己的 webroot**：`<site root>/.well-known/acme-challenge/<token>`。
   token 只接受 `^[A-Za-z0-9_-]{1,256}$`；`.well-known` 或 `acme-challenge` 是符号链接时拒绝，
   防止把一个 root 可写的令牌文件写出站点目录。验证结束立刻删除，空了就把目录收掉。
4. **CSR 与私钥都是 ECDSA P-256**，证书由 `CreateCertFromOrder` 取回；证书链与私钥通过
   `SetACMECertificate` 安装，`TLS.ACME=true` 被写进 vhost 标记，续期扫描只认这个标记。
5. **续期策略**：`RenewalDue` 在 `NotAfter - now < 30 天` 时为真；进程启动 10 秒后扫一次，
   之后每 12 小时扫一次。只扫 `TLS.ACME` 的站点，逐站加锁，失败只记录并等下轮——
   不做"失败取消自动续期"这种隐藏状态。

API 与开关：`POST /api/v1/sites/{name}/acme`，请求体 `{"redirect": bool}`；
`redirect` 决定 80 端口是否强制跳转 443（challenge 路径始终豁免）。通配符域名在写任何配置之前
就返回 `422 acme_unsupported`，不会留下半张证书。签发失败返回 `422 acme_failed` 并带原因。
`MINI_PANEL_ACME_DIRECTORY` 覆盖 ACME 目录（默认 Let's Encrypt 生产环境），
`MINI_PANEL_ACME_CA_FILE` 指定私有 CA（Pebble 集成测试用它），两者都只在部署/测试时使用。
HTTP 触发的那次签发经过 `auditWrites`，会留下一条审计；后台续期只写日志——它没有请求主体，
也不该伪造一个。

**不做**：DNS-01、通配符签发、EAB、多 CA 账户管理、把 ACME 账户密钥导出到 API。
"证书列表里每张都能手动续期"仍是后续片的事；本片只有"按站点签发 + 自动续期"。

### §5.5 站点 PHP 版本绑定（M2 第六片落地）

这一节只描述**已交付**的绑定路径；它故意比"PHP 多版本管理"窄得多。

* **绑定的是已有后端，不是新建后端。** `resolvePHPBinding` 先跑一次 `php.Discover()`，
  只接受本机探测到、且带 fpm 的版本；版本不存在或只有 cli/cgi 时返回 `ErrSitePHP`，
  写配置之前就失败。面板**不创建 per-site pool**，也不安装 PHP——那是 `php` 一项尚未交付的
 另一半。
* **vhost 里只多一个 handler 和一个 index。** `.php` location 固定为
  `try_files $uri =404;` + `include fastcgi_params;` + 显式
  `SCRIPT_FILENAME $document_root$fastcgi_script_name` + `fastcgi_pass unix:<socket>;`；
  index 改为 `index index.php index.html index.htm;`。socket 路径与版本写进
  `# minipanel-site:` 标记，删除站点或升级旧配置时随标记一起读回。
* **写纪律不变。** `SetPHP` 与创建站点一样走"写配置 → `nginx -t` → 通过才 reload"，
  任一步失败恢复上一份文件；证书操作重渲染时也会保留 PHP 绑定。
* **能力位图的分工。** `php_version_switch` 只在"站点写入可用 + 探测到带 fpm 的版本"时
  `available`；`php_fpm_versions` 只列带 fpm 的版本，是页面选择器的唯一来源。
  清空绑定（`php_version` 为空）是救援路径，不受该能力位图拦截。
* **不把 socket 存在说成后端可用。** 站点行上的 `php_socket_state` 是 `internal/php`
  对 `/proc/net/unix` 的现场读；`listening` 才表示此刻有进程在听，其余状态页面明说
  "站点会 502"。绑定成功不等于 PHP 能跑。

API：创建站点时请求体可带 `php_version`；已有站点用
`PUT /api/v1/sites/{name}/php`，`{"php_version": "8.3"}` 切换、空串清空。
能力不可用时选择版本返回 `403 capability`，清空仍放行；版本无效或没有 fpm 返回
`422 php_unavailable`。

### §5.6 站点基础设置编辑（M2 第七片落地）

这一节描述"改一个已存在站点"的边界。它只替换三样操作者数据：域名列表、文档根目录、
默认文档列表；站点名、PHP 绑定与证书文件都不动。

* **全量替换，不是补丁。** `PUT /api/v1/sites/{name}` 的请求体是
  `{domains[], root?, index?}`。`domains` 必须给全（1-20 个，和创建同一套主机名校验与去重）；
  `root` 省略或为空表示保留当前目录；`index` 省略或为空表示恢复内置列表
  （绑定 PHP 时 `index.php index.html index.htm`，否则 `index.html index.htm`）。
* **默认文档是文件名，不是路径。** `validateIndex` 只接受 1-64 位字母/数字/点/下划线/连字符、
  最多 10 项，拒绝 `..` 与任何路径分隔符；未绑定 PHP 时拒绝 `.php` / `.phtml` / `.phar` 项——
  nginx 会把它们当普通文本返回，等于把源码交给访客。绑定 PHP 的站点可以选择 `index.php`；
  反过来，**清空 PHP 绑定前必须先把这个自定义项改掉**，`SetPHP` 会拒绝让静态站点继承它。
* **证书覆盖先于写入。** 域名变更且 `TLS != nil` 时，`SetBasics` 从 `CertDir` 读回现有证书与私钥，
  用 `validateCertificate` 对新域名集合重新校验。覆盖不了就返回 `ErrTLSInvalid`（API 为
  422 `invalid_tls`），配置文件一个字节都不写；缩窄到证书已覆盖的子集则允许。这样不会出现
  "vhost 声明了 new.example.com、`ssl_certificate` 还是 old.example.com"的错配。需要换名字时，
  先关闭 HTTPS、编辑域名，再重新签发或上传。
* **根目录创建与回滚。** 新根目录不存在时以 0755 创建；随后的 `nginx -t` 或 reload 失败，
  `applyConfig` 先恢复上一份配置，调用方再删除刚建的空目录。旧根目录及其内容从不移动、不删除
  ——改配置不是搬数据。
* **写纪律不变。** 仍然走"写配置 → `nginx -t` → 通过才 reload"；`render` 重写 vhost 时保留
  TLS 与 PHP 字段，`SetBasics` 成功后返回的站点行含新的 `domains` / `root` / `index`。
  `index` 写进 `# minipanel-site:` 标记，页面下次读取时原样回填。

API：`PUT /api/v1/sites/{name}`；成功 200 + 站点行，参数不合法 400 `invalid_site`，
证书覆盖不了 422 `invalid_tls`，nginx 拒绝 422 `nginx_rejected`，站点不存在 404 `not_found`。

### §5.7 站点伪静态模板（M2 第八片落地）

这一节描述"给站点选一套重写规则"的边界。它是**封闭模板集**，不是一个可以填任意 nginx
指令的配置编辑器；`site_write` 的语义仍然只是"改面板自己写出的 vhost"。

* **模板 ID 是词汇表，不是内容。** `GET /api/v1/sites/rewrite-presets` 返回五项：
  `none`（默认 `try_files $uri $uri/ =404`）、`wordpress`、`laravel`、`thinkphp`、`spa`。
  `PUT /api/v1/sites/{name}/rewrite` 的请求体只有 `{preset}`；服务端 `validateRewrite`
  拒绝未知 ID，`rewriteLocation` 把它映射为固定的 `try_files` 片段。调用方提交的任何配置文本
  都没有入口——这既挡住了注入，也保证页面选项与后端白名单不会漂移（列表本身也由后端提供）。
* **PHP 依赖是双向的。** `wordpress` / `laravel` / `thinkphp` 的回退目标是 `/index.php`，
  因此 `RequiresPHP` 为真：静态站点选它们返回 400 `invalid_site`；反过来，站点正在使用这些
  模板时 `SetPHP` 拒绝清空 PHP，必须先切回 `none` 或 `spa`，否则 nginx 会把 `index.php`
  当普通文本返回，等于交出源码。`spa` 回退到 `/index.html`，纯静态站点可用。
* **写纪律不变。** `SetRewrite` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才 reload，
  任一步失败恢复原字节；模板 ID 写进 `# minipanel-site:` 标记，`List` 下次读取时原样回填。
  marker 里出现未知或不合法的 `rewrite` 值，该文件不会被当作面板站点（`foreign` 语义）。
* **范围。** 这一片不提供自定义规则、不下载第三方规则、不做按目录的局部重写；防盗链等
  其它 `site_write` 子项仍未交付，仍以带理由的灰项呈现。反向代理已随第九片交付，
  整站跳转已随第十片交付，它们与伪静态互斥（§5.8、§5.9）。

API：`GET /api/v1/sites/rewrite-presets` 返回 `{items:[{id,label,description,requires_php}]}`；
`PUT /api/v1/sites/{name}/rewrite` 成功 200 + 站点行，未知模板 400 `invalid_site`，
站点不存在 404 `not_found`，nginx 拒绝 422 `nginx_rejected`。

### §5.8 站点反向代理（M2 第九片落地）

这一节描述"把一个站点整站转发到另一个上游"的边界。它是**单个上游 URL 的固定模板**，
不是一个可以填任意 `location` 或 `proxy_pass` 参数的配置编辑器。

* **输入只有一个 URL 和一个开关。** `PUT /api/v1/sites/{name}/proxy` 的请求体是
  `{target, websocket}`。服务端用 `url.Parse` 解析 target，再按 scheme / host / port / path
  重新拼出规范化结果：只接受 `http` / `https`；主机名按 DNS 标签校验，IP 字面量交给
  `net.ParseIP`；端口限定 1-65535；路径只允许受限字符集且拒绝 `..`。userinfo、查询串、
  片段、控制字符以及 `; { }` 引号反斜杠 `$` 反引号等 nginx 元字符一律拒绝——调用方不能借
  URL 注入指令。长度上限 255 字节。
* **生成的指令是固定的。** `proxy_pass <target>;` 加 `proxy_http_version 1.1;` 与
  Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto 四个头；`websocket=true` 时再追加
  `Upgrade` 与 `Connection "upgrade"` 两行。没有 header 改写、路径重写、超时、缓冲或缓存
  参数入口；缓存开关未交付。
* **清除代理始终允许。** `target` 为空字符串表示删除代理块，`location /` 回到默认的
  `try_files $uri $uri/ =404`。这是救援路径，不受任何额外前置条件拦截；但 `websocket=true`
  配空 target 返回 400 `invalid_site`，避免表单误操作留下"只有升级头"的怪状态。
* **与伪静态、整站跳转互斥。** 三者都写 `location /`，因此 `SetProxy` 在站点使用非 `none`
  模板或正在整站跳转时拒绝；`SetRewrite` / `SetRedirect` 在站点已启用代理时同样拒绝；
  `parseMarker` 遇到同时带多种所有者的文件，不把它当作面板站点。先把一边清空再启用另一边
  （整站跳转见 §5.9）。PHP 绑定不受影响：`.php` 是正则 location，优先于 `location /`，可以与代理共存。
* **写纪律不变。** `SetProxy` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才 reload，
  任一步失败恢复原字节；代理目标与 WebSocket 布尔值写进 `# minipanel-site:` 标记，
  `List` 下次读取时原样回填。marker 里的 target 会重新走一遍同样的校验。
* **范围。** 不提供上游组 / 负载均衡 / 健康检查、多 location 分别代理、header 增删改、
  WebSocket 之外的协议升级，也不提供"代理到 unix socket"的入口；这些仍以带理由的灰项呈现。

API：`PUT /api/v1/sites/{name}/proxy` 成功 200 + 站点行；target 不合法或与伪静态冲突
400 `invalid_site`；站点不存在 404 `not_found`；nginx 拒绝 422 `nginx_rejected`。

### §5.9 站点整站跳转（M2 第十片落地）

这一节描述"把一个站点整站跳到另一个地址"的边界。它是**单个绝对 URL 与固定 `return` 行**，
不是可以填任意 `rewrite` / `if` / 正则的配置编辑器。

* **输入是一个 URL、一个状态码和一个开关。** `PUT /api/v1/sites/{name}/redirect` 的请求体是
  `{target, code, keep_path}`。target 与反向代理共用 `parseUpstreamURL`
  （`internal/nginx/proxy.go:54`）：`url.Parse` 后按 scheme / host / port / path 重新拼出
  规范化结果，只接受 `http` / `https`，拒绝 userinfo、查询串、片段、控制字符与 nginx 元字符，
  长度上限 255 字节。非空 target 时状态码必填，只接受 301 或 302；0、307、308 等其余值
  一律 400 `invalid_site`。清除跳转时状态码与保留路径一并忽略。
* **生成的指令只有一行。** `return <code> <target>;`；`keep_path=true` 时变成
  `return <code> <target>$request_uri;`。目标尾部斜杠在拼接前去掉，避免 `//a/b`。
  没有 flags（`last` / `break`）、没有正则、没有条件、没有按路径分别跳转的入口。
* **清除跳转始终允许。** `target` 为空字符串表示删除 `return` 行，`location /` 回到默认的
  `try_files $uri $uri/ =404`。这是救援路径；此时 `code` 与 `keep_path` 一并忽略，
  避免表单残留值阻止清除。
* **与伪静态、反向代理三者互斥。** 它们都写 `location /`，因此四处强制：`SetRedirect`
  在站点使用非 `none` 模板或已启用代理时拒绝；`SetProxy` 在站点正在跳转时拒绝非空 target；
  `SetRewrite` 在站点正在跳转时拒绝非 `none` 模板；`parseMarker` 遇到同时带多种所有者的
  文件（`proxy` / `redirect` / 非 `none` 模板计数大于 1），不把它当作面板站点。
  先把一边清空再启用另一边。PHP 绑定不受影响：`.php` 是正则 location，优先于 `location /`。
* **写纪律不变。** `SetRedirect` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才
  reload，任一步失败恢复原字节；目标、状态码与保留路径写进 `# minipanel-site:` 标记，
  `List` 下次读取时原样回填。marker 里的跳转字段会重新走一遍同样的校验，非法值使文件
  落到 `foreign` 语义而不会被列出。
* **范围。** 不提供按路径的跳转表、正则匹配、排除规则、307/308、跳转到相对路径或内部
  location；这些仍以带理由的灰项呈现。

API：`PUT /api/v1/sites/{name}/redirect` 成功 200 + 站点行；target / code 不合法或与伪静态、
反向代理冲突 400 `invalid_site`；站点不存在 404 `not_found`；nginx 拒绝 422 `nginx_rejected`。

## §6 面板自身暴露与访问控制

### §6.1 是什么、不是什么（沿用 M0 的口径，不许漂）

访问控制只有四样：监听地址、会话令牌与有效期、IP 白名单、CSRF + 失败锁定。
**入口路径是掩护不是鉴权**，伪装响应同理；拿到有效会话就能从任意路径访问面板，这一点在
M1 的逐路径收紧完成前不改变，任何文档（含本文件）都不许把入口描述成登录后的防护。

### §6.2 与参照系的三点差异

1. **失败锁定按身份**：`ip|username` 为键 + 指数退避封顶 1h。参照系里面板登录失败锁定几乎没人
   真做：1Panel 用验证码（且该验证码曾被客户端参数绕过，公开 issue 可查），Cockpit 用
   `MaxStartups` 限并发，其余交给系统 fail2ban。宝塔的阈值是每 IP 5 次即锁（其文档与界面可见）。
   我们不采用纯按 IP 的计数，理由是这类键一旦不含身份，同一出口 IP 上一个被爆破的用户名就能把
   运维一起锁在门外——这是设计层面要回避的后果，不是对别人实现的源码断言。我们的键含用户名，
   锁定期内正确口令也拒，未知用户与错口令响应完全一致（已交付，`m0_test.go:307/481`）。
2. **凭据不发明文**：无 TLS 且监听在可路由地址 → 一律 `503 tls_required`，fail-closed。宝塔的
   登录脚本里有一条**可由攻击者主动触发**的降级分支（取不到公钥时直接明文提交），我们从不做
   客户端加密包装，因此那条分支不存在——这不是更强的加密，而是少一个失败模式。
3. **不给自己开后门**：不做免登录临时访问授权、不做免登录文件分享、不做端口隧道、不做内嵌反代。
   这四条在参照系里都存在，也都把"面板的访问控制"变成了"内部服务的访问控制"。

### §6.3 自救对称表（逐条核对，7 项全部达标；G-A/G-B/G-C 已在 M1 闭合，表体已进代码）

这张表现在是**代码里的一份数据**而不是本文的一张清单：`internal/lockout/lockout.go:52 Risks()`
按下面 7 行的顺序产出 9 行（监听/TLS 拆成"监听地址 / 端口"与"面板证书"两行，口令行之外另加
"口令待确认"——`minipanel passwd` 置的 `must_change_pw` 是实际会拦住请求的那一项）。
`docs/里程碑.md` 的 M1 一节与 `README.md` 的 CLI 一节指向同一份实现。

| 2FA | 手机丢 / 时钟漂移 | `minipanel reset-2fa --clear [--user <账号>]`（`main.go:854`，同时作废该账号全部会话） | ✅ G-C |
| IP 白名单 | 写错一个字符 → 所有请求 403 `ip_not_allowed`，**包括修复它的那个请求** | `minipanel reset-ips --set <列表> / --clear`（`main.go:795`，只动 SQLite 设置项） | ✅ G-A |
| 口令有效期 | 可写不可执行，写了没反应（不是关在外面，是虚假安全感） | 执行点已落地：`auth.go:155 passwordExpired()` → `server.go:347 passwordGate()`，到期只放行改密与登出 | ✅ G-B |

G-A / G-B / G-C 三条原本"排在任何新页面前"，现已全部闭合。落地的形态与当初的修法一致：

```
G-A  minipanel reset-ips            [--set <cidr 列表> | --clear]   # 只动 SQLite 设置项，panel.json 无关
G-B  口令有效期执行点：到期 → passwordGate 只放行 /session、/password、/logout
G-C  minipanel reset-2fa            --clear [--user <账号>]         # 关掉 2FA 并作废该账号全部会话
     一次性恢复码：仍未做（原方案里就标为"可选加分项"）
```

同步要求现在由测试兜着，而不是一句约定：新增一条 `reset-*` 时，它要进 usage 文案
（`TestUsageCoversEveryCommand` 逐条比对 8 个子命令与 8 个 flag），要进上面这张表
（`internal/lockout/lockout.go` 加一行），而表里写的每条命令与每个 flag 又必须真的存在——
`cmd/minipanel/lockout_test.go` 拿表里的文本去 `dispatch()` 试一个不存在的 flag，
再逐条回查 usage。**方向是反的**：不是"命令改了记得改文档"，而是"表里写了一条不存在的命令就红"。
不进 `openapi` 的仍然是**命令本身**（CLI 不是 API 面）；M1 之后进规格的是这张表的**只读视图**
`GET /api/v1/lockout-risks`，它不执行任何东西，§3.10 的「CLI 对照」页渲染的就是它。

## §7 备份设计（M6，但语义现在就定）

四条被参照系证明"便宜但直接决定可信度"的规则，现在写死，避免 M6 时重新讨论：

1. **保留 N 份只计成功**。失败记录不占保留额度，否则备份目录会被失败挤满而"看起来有备份"。
2. **上传后 `存在 + 大小` 双校验**，结果写进执行报告；校验失败 = 任务失败。"你去存储桶自己看一眼"
   不是可验收的备份。
3. **恢复前先自动备份当前状态**，恢复步骤落 checkpoint，中断可从中间步续跑；`Restore` 是写操作，
   因此受 §5.2 约束。
4. **预检**：目标可达（试传）、空间 ≥ 2× 估算、时区一致；不足时给分条解法，不给一个错误码。

两条边界：
- **对象按粒度分件**（站点 / 库 / 配置 / 面板自身各成一件），恢复入口允许"只恢复一个库"。
  整包 tar 的代价在参照系里有据可查：用户想恢复一个邮箱就得动整包。
- **文档必须写清"面板备份不含什么"**（容器数据卷、非面板创建的目录、云厂商快照）。
  这句比"含什么"更能防误解。
- **面板自身状态要不要备**是必答问题：M6 包含面板 SQLite + `panel.json` + 配置历史目录，
  不含第三方云凭据的明文（凭据本身 0600 在库里，备份出去等于把凭据带走，需在预检里警告）。

## §8 不做清单

分四组。理由列只允许指向成文纪律或可核验的公开事实。

### §8.1 会破坏"自主可控"定位的

| 不做 | 理由 |
| --- | --- |
| 软件商店 / 插件安装 / 第三方应用一键部署 | 以 root 拉取并执行任意第三方代码，同时摧毁"单一二进制 / 不引入 cgo / 不做面板自更新"三条纪律；且长尾模块每一个都是攻击面（参照系：Webmin 127 个模块目录至今含 `minecraft`） |
| 面板内任意 URL 下载器、URL 访问型计划任务 | SSRF 面，可直接打内网元数据服务。参照系里同类入口有公开公告 |
| 任意参数的命令执行器（Webmin Custom Command 一类） | 官方承认导致 root 提权。需要执行就走已鉴权、可审计、可录像的终端 |
| 免登录文件分享 / 临时登录授权 / 内嵌 phpMyAdmin 反代 / 端口隧道 `/p/<port>` | 把面板端口变成第二张网，等于"面板的访问控制 = 内部服务的访问控制" |
| 面板自更新 / 在线升级 / 首页"修复"按钮 | 升级 = 换二进制；schema 只向前；回滚 = 回旧二进制。运行时自我改写使版本与审计失去意义 |
| 遥测 / 崩溃上报 / 云端账号绑定 | `/healthz` 里 `telemetry:false` 是事实陈述；验收有一条 grep 断言非测试代码无出站调用 |

### §8.2 参照系里存在但收益/成本比不成立的

| 不做 | 理由 |
| --- | --- |
| 站点级 WAF / 防篡改 / 签名扫描 / 安全评分 | 评分不可验证（参照系里同类评分给出 30/100 却无法说明"100 长什么样"）；扫描需持续签名库更新，把判断权交给外部 |
| 邮件 / DNS 权威 / FTP 托管 / 邮局 / WordPress 套件 | 均非"面板"职责：投递声誉、25 端口被普遍封、额外公网端口面，成本全在运维侧 |
| 多节点 / 跨节点文件互传 / 整机迁移 / 集群负载 | 需要保管对端 root 凭据（§9 未决）；集中管理该用 Agent 模型，不是浏览器里缝 N 台 |
| AI 网关 / 模型管理 / Benchmark / 终端里的 AI 分析 | 方向性押注，与"把这台机器管明白"无关；把操作日志与终端上下文交给第三方分析与"每次操作只在本机留痕"相反 |
| 容器管理页（生命周期 / Compose / 镜像 / `daemon.json`） | 见 §8.3 唯一保留项。接管 Docker 等于接管一台机器；且 `daemon.json` 改动可能让面板自己失联 |
| 计划任务命令黑名单 | UI 写死 `shutdown/mkfs/passwd` 是假安全感：一条 `sh -c "s""hutdown"` 就绕过，同时给用户"面板替我决定"的错觉。改为脚本进审计 + 快照 + 无提权语义 |
| 首页卡片自定义 / 主题 / logo / 终端配色 / 备忘录 | 装饰性支出；单机自用 |
| DHCP / VLAN / Wi-Fi / 访客网络 / Mesh / 流量整形 / QoS / DNS 过滤 | 路由器功能盘里 61 项中"不搬"的 14 项：服务器不给别的设备发地址，界面永远空转 |

### §8.3 看起来是"不做"、其实换了形状的（保留判断）

| 参照系做法 | 我们的替代 |
| --- | --- |
| 应用商店一键部署 | **本地静态站点模板 + Nginx 配置片段库**（值 80%，零下载、零执行第三方代码） |
| 容器管理 | **只读暴露面**：Docker `-p` 造成的监听与规则来源必须出现在 §3.1/§3.5，不出现"启停容器"按钮 |
| 配置要求"你自己去装 firewalld" | `degraded` + 一条可复制命令 + 一个 `verify` 复查链接（§4.2） |
| 免登录分享文件 | 审计导出走 CLI（`minipanel audit export`），不开下载端点 |
| 整机快照备份 | 面板状态（SQLite + `panel.json` + 配置历史）纳入 M6 备份对象，但不含第三方云凭据明文 |

### §8.4 与"未排期"的区别

`未排期` = 现在不做、但没在 §8 里被判死刑，且**代码里必须已经有对应 Deny 理由或干脆没有 key**。
不做（§8）= 明确拒绝，写理由。混淆这两者就会重新产生"菜单里有、点了是空的"。

## §11 验收增补

每条新纪律都要有一个能失败的测试，否则它只是文案。

| 设计断言 | 测试 |
| --- | --- |
| 每个 `state != available` 的 key 必须有非空 `reason` | 扩展 `capabilities_test.go`：白名单机制不变，另加"四态结构完整性"（`degraded`/`foreign` 允许 `fix_action=null`，`unavailable` 必须有 `reason`） |
| 写端点返回 `affected` 且快照已落盘 | 每个 Provider 一个用例：改 → 断言 `config-history` 下有对应字节 → 回滚 → 断言与原文件一致 |
| 回滚不产生无限快照链 | 断言深度上限生效 |
| `foreign` 对象不可写 | 构造一条非面板来源的规则/站点，PUT 必须 `403`/`409` 且原因含来源 |
| `fix_action` 不含包名/URL/命令 | 契约层校验 `fix_action.kind ∈ {panel, copy_command, verify}` 且 `copy_command` 来自静态白名单 |
| 路径参数只许 `{key,id,name}` | `contract_test.go`（A9） |
| 文件路径不进 URL | 断言 `POST /files/*` 形态不存在，只有 `/api/v1/files` + 请求体 |
| IP 白名单写错不会把人关死 | CLI 用例：写入一个排除当前 IP 的白名单 → `minipanel reset-ips --clear` → 能登录 |
| 2FA 复位出路 | CLI 用例：启用 2FA → `reset-2fa --clear` → 口令登录可用（若做恢复码，另测一次一码） |
| 备份只计成功 | 造两次失败 + 一次成功，`retention=1` 断言只剩成功那份 |
| 备份 Exist+Size 校验 | 假后端返回大小不符 → 任务状态 `failed` 且报告含校验字段 |
| 无出站网络 | 现有 grep 验收（`Makefile`/验收 #17）保持为空；新增 handler 不得引入 `net.Dial` |

## §12 与三份研究的差异（我否掉或改了什么）

1. **把 `config_history` 从 M6 拆到 M2（协议）+ M4（UI）**。研究档案建议 M6，我认为错：M4 的防火墙
   写入如果早于撤回能力上线，那么撤回能力最该在的那天恰好没有。
2. **拒绝给能力位图加第五态**。档案建议 `{available|degraded|unavailable|foreign}` 之外再加
   `pending`（"可写但未生效"）。我不加：那是缺陷不是状态，正确修法是 A2 删掉 `basic_auth`、
   §6.3 G-B 补上有效期的执行点。留着 `pending` 就等于把"有按钮无逻辑"制度化。
3. **拒绝 `fix_action` 承担装包**。档案建议学 Cockpit 的 "Enable PCP metrics collector" 一键补齐。
   这条我不照抄：我们不在运行时安装任何东西（§4.2 三类边界）。改成"给一条可复制的确切命令 +
   事后复查入口"，收益相近、纪律不破。
4. **拒绝把逐连接/监听塞进 `monitor`**。档案也建议拆开，这里一致；但我把 `listeners` 提到 M4 的
   理由换成 §1.5（暴露面是主语），不是为了图表性能。
5. **否掉远端主机/批量输入到所有连接**（1Panel 的终端有）。效率是真的，但它同时需要凭据保管、
   目标确认和"改错一批机器"的回撤能力，三者现在都没有答案 → §9 未排期。
6. **否掉计划任务的命令黑名单**（同类面板 UI 里写死 `shutdown/mkfs/passwd`）。这是假安全感，
   且与"运维本人就是管理员"的定位矛盾。
7. **否掉安全评分**，保留 `doctor` 式的一次可复查状态输出。
8. **容器：从"整个模块不做"改为"只做只读暴露面"**。档案建议归到"范围外"；我保留了
   Docker 规则来源与监听归属的可见性，因为隐藏它会让防火墙页骗人（§1.2、§8.3）。
9. **告警通道从六类砍到两类**（邮件 + Webhook，默认关闭）。其余四类各是一次长期集成，
   收益由 M6 之后的真实使用决定。
10. **不搬路由器面板的 14 项**（DHCP/VLAN/Wi-Fi/QoS/DNS 过滤/多站点 Mesh 等）：全盘采纳档案的
    "不搬"判定，没有例外。
