# Mini Panel 功能设计

> 本文件是**功能范围的决策记录**：模块怎么切、页面有哪些、每个功能点要占哪个能力位图 key、
> 走哪些接口、落在哪个里程碑，以及明确不做什么。
>
> 它与仓库其他文档的分工是：`技术选型与MVP规格.md` 管**怎么做**（栈、约束、纪律），
> `里程碑.md` 管**什么时候算做完**（验收），本文件管**做什么、不做什么**。
>
> **措辞约定**：本文点名竞品时，只写**可从其公开文档、公开前端资产或本机界面上直接观察到的行为**，
> 不引用闭源产品的源码内部路径、行号或代码片段，也不引用只在内部调研档案里存在的取证细节
> （那些档案不进仓库）。开源项目（1Panel / Cockpit / Webmin-Virtualmin / CloudPanel / Portainer /
> HestiaCP / pfSense / OPNsense / RouterOS / LuCI）一律按公开出处引用。
> 凡写"参照系里只有某项目做到"，后面必须能给出该项目的公开出处，否则降级为"我们的判断"。
>
> **落地的唯一顺序**（继承 `技术选型与MVP规格.md` §8.2）：先有跨平台实现与路由 → 再改
> `internal/platform/capabilities_test.go` 的白名单 → 最后才改本文与 `里程碑.md`。
> 反过来写就是超前承诺。所以本文里所有里程碑调整都是**待执行的改动清单**（§10），不是既成事实。

## §1 六条立场

后面每一节的取舍都从这六条推出来。这六条不是愿望，是**已经在代码里或即将在代码里的约束**。

**1.1 界面唯一的渲染依据是服务端能力位图，位图从"能不能"升级为"处于什么状态"。**
参照系里没有人把能力位图做成对用户可见的一等公民：最接近的三种做法是模块清单里的
`os_support` 声明、`virtualmin list-features` 这种可查询接口，以及 Cockpit 的"整块隐藏 + 降级 +
给一个补齐前置的按钮"。1Panel 的引擎层已经按后端拆了能力接口并定义了
`ErrAdapterUnavailable / ErrInventoryUnavailable / ErrFamilyUnavailable`，但文档仍然要求用户
"自己去装 firewalld" —— 引擎能力化了，UI 没能力化。我们两步一起做（§4）。

**1.2 面板只承诺管理"自己创建的对象"；其余一律可见但只读，并标出真实来源。**
这条决定了很多页面的形状。它同时解决两个参照系里都存在的问题：接管别人写的配置会导致状态
不可控（1Panel 的 Compose 只允许编辑自己部署的，Hestia 的 `system` 套餐不可改），而只显示
"我加的规则"的防火墙列表则在骗人（Docker `-p`、k8s NodePort 就是主机版 UPnP，会绕着面板改内核
规则；pfSense 对 UPnP 动态规则的做法是"让它可见、可辨认"，不是假装不存在）。

**1.3 写操作是三段式：预检 → 快照 → 执行并回报影响清单。"可回滚"是功能，不是提示文案。**
路由器面板在这点上比服务器面板成熟：pfSense 的配置历史明写每条记录含改动人、来源 IP 与修订号，
改坏了有四层出路。我们的审计已经记 actor/IP/time/`params_hash`，但记的是**事件**而不是**状态快照**
—— 这是当前最大的自救缺口。因此快照不打算等 M6，而是作为写协议的一部分从 M2 起就存在（§5）。

**1.4 每个能把用户关在外面的开关，必须有一条对称的 SSH 侧解锁命令。**
参照系里这是共同底线：`1pctl reset entrance/ips/mfa/https/domain`、CloudPanel 的 CLI 关 2FA、
Portainer 的 `reset-admin`、Hestia 的 `v-change-*`；Cockpit 干脆不建自己的账号体系来规避。
我们现有 `init / doctor / passwd / reset-entrance` 四条，逐条核对后有**两个"能把自己锁死却没有
出路"的缺口**（IP 白名单、2FA）和**一条"设置项可写但无执行点"的虚假安全感**（口令有效期），
见 §6.3。G-A / G-C 是本文新增到 M1 的两条（§10 A1）；G-B 的条目本来就在 M1
（`docs/里程碑.md` 的 M1 表里「口令有效期真正生效」那一行），这里做的只是把它从"前端换代时顺带做"提到"第一件事"。三条都排在
任何新页面之前。

**1.5 暴露面是这类面板的主语，而不是防火墙页的一个子功能。**
"我从外面看得见吗"和"面板开在哪张脸上"是两个问题，M0 只回答了后者的机制部分。
所以概览页必须回答三张脸（公网 IP / 内网 IP / 回环）+ 谁在监听 + 现在有哪些连接，
而这三项的成本只是读 `ss` 和一次真实解析（§3.1、§3.5）。

**1.6 范围靠"负担档"守，不靠"必备档"堆。**
参照系里最能说明膨胀代价的是 Webmin 的 127 个模块目录（`adsl-client`、`minecraft`、`sgiexports`
至今仍在，每一个都是 CVE 面）和它官方列出的提权/SSRF 公告清单；1Panel 则把 AI 网关整块塞进
v2、同时把 WAF/uptime/多节点划进付费档。**"面板里可传任意参数的命令执行器"和"可下任意 URL 的
下载器"是提权入口，不是功能**（参照：终端能做同样的事，差别在于终端在登录控制和审计里可见）。
§8 的不做清单比 §3 的页面清单更重要。

## §2 模块划分

10 个一级模块。导航顺序 = 用户排查一台陌生服务器时的动手顺序。

| # | 模块 | 路由 | 它回答的问题 | 明确不在这里的东西 |
| --- | --- | --- | --- | --- |
| 1 | 概览 | `/overview` | 这台机器现在什么状态、我从哪张脸能看到它、有没有正在烧的东西 | 任何写操作（概览只读，按钮一律跳到归属模块） |
| 2 | 网站 | `/site/*` | 有哪些站点、每个站怎么被服务、证书什么时候到期、PHP 版本与扩展 | 容器；应用商店；站点级 WAF |
| 3 | 数据库 | `/database/*` | 有哪些实例/库/账号、能从哪里连、慢在哪 | phpMyAdmin 内嵌反代（§8） |
| 4 | 文件 | `/file` | 看/改/传文件与属主权限 | 回收站、文件历史、免登录分享（§8） |
| 5 | 安全 | `/security/*` | 内核放行了什么、谁写的、命中没有、面板自己被保护成什么样 | 签名库扫描；fail2ban 全 jail 可视化 |
| 6 | 监控与服务 | `/monitor/*`、`/service/*` | 指标历史、逐连接、systemd 单元与进程 | GPU/AI 维度；多主机聚合 |
| 7 | 终端 | `/terminal` | 改坏了要能进系统自修 | 远端主机凭据保管与多主机批量输入（§9） |
| 8 | 任务 | `/task/*` | 计划任务、备份、配置版本与回滚 | 亚秒自建循环冒充 crontab（§8） |
| 9 | 日志与审计 | `/log/*` | 谁动了什么、按对象聚合的时间线 | 可被面板清空的审计（永不做，§8） |
| 10 | 设置 | `/config/*` | 面板自身访问控制、账号与 2FA、会话、告警、能力矩阵 | 主题/水印/logo |

模块与现有位图 key 的对应关系：`site` / `php` / `php_ext_source` / `ssl` 归 2；`database` 归 3；
`file_posix_perms`（+ 提案 `file_manager`）归 4；`firewall` / `firewall_write`（+ 提案 `listeners`
`connections`）归 5 与 6；`monitor`（+ 提案 `service`）归 6；`terminal` 归 7；`cron` / `backup`
（+ 提案 `config_history`）归 8；`audit` 归 9；面板自身安全在 10（M0 已交付，不占新 key）。

## §3 页面清单 × 能力 key × 里程碑

状态词表：`已交付` = 代码与测试都在；`M1`…`M6` = 计划内；`M4 后` / `未排期` = 未进里程碑；
`不做` = §8 明确拒绝；`提案` = 本文新提的 key 或接口，尚未进代码。

### §3.1 概览 `/overview`

| 页面/区块 | 功能点 | 能力 key | 里程碑 | 备注 |
| --- | --- | --- | --- | --- |
| 概览 | 主机身份（发行版、内核、架构、运行时长、面板版本） | `monitor`（读侧） | 已交付 | `GET /api/v1/system/info` |
| 概览 | 资源仪表（CPU/内存/磁盘/负载）+ 时间序列 | `monitor` | M4 | 采样率与保留期可配、可关（参照 Cockpit 归档 vs 实时） |
| 概览 | **三张脸**：公网 IP / 内网 IP / 回环，各自可达性 + 主机名解析一致性 | `net_view`（提案） | M4 | 公网侧只允许问"我看到的自己是谁"，靠本地读取 + 一次已配置的对端；不做任意 URL 探测（§8.1） |

| 概览 | 首页卡片可勾选自定义 | — | 不做 | 单机自用，固定布局先落地；自定义属装饰性支出 |
| 概览 | 备忘录 | — | 不做 | 不是运维功能 |

## §4 能力位图契约 v2（提案）

### §4.1 从 bool 到四态

提案的起点是 v1：`features[key] = bool`，`false` 时另有一个 `unavailable[key]` map 装理由。
这个 bool 已经比参照系好（它只能表达"能 / 不能"），但实际状态有四种，混在一个 bool 里就会
重新产生"点了才知道失败"。下面这张形状是 M1 落地的东西，不是待办：
`Feature{State, Reason, FixAction, Verify}`（`internal/platform/capabilities.go:121`），
`Features map[string]Feature`（`internal/platform/capabilities.go:163`）。v1 那个和 `features`
可以各说各话的平行 map 已经删掉，规格里写着这条删除（`internal/api/openapi/panel.yaml:160-162`），
页面上也没有它的位置（`web/src/views/CapabilitiesView.vue:38 featRow()` 只读 `features[key].state`）。

```jsonc
"capabilities": {
  "features": {
    "firewall_write": {
      "state": "degraded",                 // available | degraded | unavailable | foreign
      "reason": "ufw 后端可用，但 iptables 规则表里有 4 条不是面板写入的，面板不会改写它们",
      "fix_action": null,                   // 可执行的一步（幂等、有界）；没有就 null
      "verify": "GET /api/v1/security/firewall/rules?source=foreign"  // 用户如何自己确认
    }
  }
}
```

| state | 语义 | UI 表现（三选一，不允许第四种） |
| --- | --- | --- |
| `available` | 本版本、本机、此刻真能做 | 正常控件 |
| `degraded` | 主路径可用，某一支不可用或缺前置 | 控件可用 + 顶部一条"能用但少了 X"；缺前置且我们能补时给 `fix_action` 按钮 |
| `unavailable` | 这一版没做，或本机条件不成立 | **不隐藏**：禁用控件 + 一句原因 +（若适用）一个补齐前置动作或里程碑编号。只有与本机无关的模块才整块收起 |
| `foreign` | 对象存在但不归面板管 | 只读呈现 + 原因（"由 Docker 写入"/"非面板创建的 vhost"） |

迁移成本（已付）：`features` 与 `unavailable` 两个 map 合成一个是破坏性变更，四处必须同改——
`openapi/panel.yaml`、`internal/api/handleCapabilities`、`webui/dist` 消费点与
`capabilities_test.go`，漏一处就出现"接口说一套、页面画一套"。四处同改由
`TestCapabilitiesAreSelfConsistent`、`make check-contract` 与 `make check-ui`（能力 key 全覆盖那条）
分别把住。**收益**：1.1、1.2 两条立场第一次变成机器可读。

### §4.2 `fix_action` 的边界（这条最容易写坏）

"一键补齐前置"如果实现成"面板去装包"，就同时违反不装第三方代码与不引入长尾依赖两条纪律。
所以 `fix_action` 只允许三类：
① 面板自己有权限做的动作（如打开监控采样、生成自签证书）；
② 输出**可直接复制的命令**并留一行"执行完点这里复查"（把参照系里"你自己去装"变成"给你确切
一条命令 + 事后能验证"）；
③ 指向 `verify` 的只读复查。
禁止：`fix_action` 承载任意包名/任意 URL/任意命令。

落地进度与一处口径差：本文 ② 允许"一条可复制的命令"，而
`internal/api/openapi/panel.yaml:1304-1306` 对这个字段的说明写的是"不允许包名"——两处取严的那个，
所以 M2 第一处生产代码里的 `Degrade()` 调用（`internal/platform/platform_linux.go:864`）
把 `fix_action` 留空。缺的是什么写在 `reason` 里（那是给人读的一句说明，不是这个字段的载荷），
`verify` 走 ③ 的两条只读复查路径。`TestDoctorPHPRootedHostNamesTheVersion` 把这三件事钉住：
`fix_action` 必须为空、`reason` 必须点名探测到的版本、`verify` 必须同时含 `doctor` 与 `capabilities`。
要放开 ② 就得先改 `panel.yaml` 的这段描述并说明命令模板从哪来，不能在实现里先斩后奏。

### §4.3 key 命名与新增审批

新增 key 必须同时给出：语义、读/写、跨 Linux/Windows 的实现路径、`state` 由什么决定、
被哪条测试钉住。**本文提出的新 key 全是提案**，未进代码：
`listeners`、`connections`、`net_view`、`dns_view`、`file_manager`、`database_write`、
`service`、`log_view`、`config_history`、`notifications`。
`vpn` 不进提案（未排期，§9）。
顺序纪律：实现与路由 → 改 `capabilities_test.go:179` 白名单 → 改文档 → `make check-docs`（文档里的
`文件:行` 与点名的测试名由 `internal/docsync` 机检，指针漂了就红）。

### §4.4 路径参数纪律（这条挡住了新页面的设计自由度，写清楚）

`internal/api/contract_test.go:92-106` 目前只允许 `{key}` 一种路径参数，写死是为了拒绝
"名字 → 代码"的反射式分发。§3 里出现了站点、库、任务的资源标识，因此需要放宽，但只放宽**身份**：

- 允许：`{id}`、`{name}` 这类**只用于取标识**的参数，服务端强校验字符集与长度，且必须能在
  handler 里映射到一次数据库主键查询。
- 仍禁止：任何动词性/模块性参数（`{action}`、`{module}`、`{fun}`、`{cmd}`）。
- **内容选择器不进 URL**：文件路径、日志文件、任务脚本一律放请求体或查询串并各自校验，
  绝不出现 `{path}`。这条决定是文件管理器不变成遍历器的关键。

契约测试相应改为：路径参数白名单 `{key, id, name}` + 反射特征黑名单不变。

## §5 跨模块的三条写协议

这三条不属于任何单个页面，是 M2 起所有写端点共用的形状。

### §5.1 预检先于执行

每个写端点在执行前先返回一份检查结论（`{ok, checks[], blocking[]}`），不足就拒绝执行并给
**分条解法文案**。参照系里被记录的廉价预检：备份前空间 ≥ 2× 估算、存储账号先试传一个文件、
端口占用先查 `ss`、签发证书前确认 DNS 记录已生效、资源门限不满足就不开始重活。
M2 最小集：Nginx 配置语法（`nginx -t`）、端口冲突、根目录存在与可写。

### §5.2 快照先行 + 影响清单

规则：**任何跨子系统写入前，面板自己必须已经能撤回**。

- 落地形态：`<data>/config-history/<对象>/<时间戳>` 存改前字节 + 元数据（actor、来源请求、
  `params_hash`）；回滚是写操作，因此自己也要留快照（不允许"回滚的回滚"死循环：快照链有深度上限）。
- 响应形状：写成功后返回 `{affected: {files: [], units: [], ports: [], reload: bool}}`，
  同时进审计。用户应该看得到"这次动了哪些文件/端口/服务"，而不是自己去 `diff`。
- 各模块首个必须遵守的时点：M2 Nginx 配置、M2 PHP 配置文件、M3 实例配置（若开放写）、
  M4 防火墙规则（`internal/platform/paths.go:44-53` 已把 `Snapshot()/Restore()` 定成接口强制成员）、
  M6 crontab（写系统 crontab 前留备份）。
- **因此 `config_history` 的"能力"在 M2 就有，UI 页在 M4**。把它整块排到 M6 是错的：M4 一上线，
  改错一条防火墙规则就足以把人关在门外，而那天离 M6 还很远。

### §5.3 对象归属（`foreign`）

每个 Provider 读回来的对象必须带来源标记，UI 据此决定按钮形态。归属规则由数据源决定，不由
面板意愿决定：

| 对象 | 面板可写 | 只读（foreign）来源举例 |
| --- | --- | --- |
| vhost / Nginx include | 面板创建的站点 | 发行版默认站点、手工写的 conf、Certbot 改过的行 |
| 防火墙规则 | 面板写入的按注释/链标记 | `DOCKER`/`KUBE-` 链、云厂商 agent、`fail2ban-*` 链 |
| systemd 单元 | 面板生成的 unit 文件 | 包自带的 unit |
| crontab | 面板任务落独立 include 目录 | 系统 `/etc/cron.d/*`、用户手工 `crontab -e` 的行 |
| 数据库 | 面板建的库/账号 | 外部应用自建 |

配套纪律：面板**不接管**已存在的同名对象（创建时冲突就报错并指出来源），也不做"同步认领"。
这条比"支持更多场景"更能避免状态漂移，也顺带回答了"为什么列表里没有我手工加的那条规则"——
它在，但是灰的，理由写在 `reason` 里。

### §5.4 ACME HTTP-01 的边界与流程（M2 第五片落地）

这一节只描述**已交付**的那条路径。选择 HTTP-01 而不是 DNS-01 的理由是：面板必须能在
"只有一张 A 记录、没有 DNS API 凭据"的机器上工作，而 DNS-01 会把凭据保管、域名商 API、
传播延迟三件事一起拖进来。代价必须写在明处：**通配符证书签不了**，只能手工上传。

签发的固定顺序（写代码时按这个顺序，不要交换）：

1. **先改配置再签发**。`PrepareACME` 确保 80 端口块里有
   `location ^~ /.well-known/acme-challenge/`，且它排在 `return 301` 之前；旧版本写出的
   redirect 配置在这里升级。仍然是写配置 → `nginx -t` → 通过才 reload，失败回滚。
2. **账号密钥复用**。`/etc/minipanel/acme/account.key` 是 ECDSA P-256，首次创建 0600、
   父目录 0700；已存在就加载，`Register` 遇到 `ErrAccountAlreadyExists` 视为成功。
   没有这一步，第二次签发/续期会被 ACME 服务端拒绝——Pebble 集成用例连跑两次就是为了钉它。
3. **challenge 写进站点自己的 webroot**：`<site root>/.well-known/acme-challenge/<token>`。
   token 只接受 `^[A-Za-z0-9_-]{1,256}$`；`.well-known` 或 `acme-challenge` 是符号链接时拒绝，
   防止把一个 root 可写的令牌文件写出站点目录。验证结束立刻删除，空了就把目录收掉。
4. **CSR 与私钥都是 ECDSA P-256**，证书由 `CreateCertFromOrder` 取回；证书链与私钥通过
   `SetACMECertificate` 安装，`TLS.ACME=true` 被写进 vhost 标记，续期扫描只认这个标记。
5. **续期策略**：`RenewalDue` 在 `NotAfter - now < 30 天` 时为真；进程启动 10 秒后扫一次，
   之后每 12 小时扫一次。只扫 `TLS.ACME` 的站点，逐站加锁，失败只记录并等下轮——
   不做"失败取消自动续期"这种隐藏状态。

API 与开关：`POST /api/v1/sites/{name}/acme`，请求体 `{"redirect": bool}`；
`redirect` 决定 80 端口是否强制跳转 443（challenge 路径始终豁免）。通配符域名在写任何配置之前
就返回 `422 acme_unsupported`，不会留下半张证书。签发失败返回 `422 acme_failed` 并带原因。
`MINI_PANEL_ACME_DIRECTORY` 覆盖 ACME 目录（默认 Let's Encrypt 生产环境），
`MINI_PANEL_ACME_CA_FILE` 指定私有 CA（Pebble 集成测试用它），两者都只在部署/测试时使用。
HTTP 触发的那次签发经过 `auditWrites`，会留下一条审计；后台续期只写日志——它没有请求主体，
也不该伪造一个。

**不做**：DNS-01、通配符签发、EAB、多 CA 账户管理、把 ACME 账户密钥导出到 API。
"证书列表里每张都能手动续期"仍是后续片的事；本片只有"按站点签发 + 自动续期"。

### §5.5 站点 PHP 版本绑定（M2 第六片落地）

这一节只描述**已交付**的绑定路径；它故意比"PHP 多版本管理"窄得多。

* **绑定的是已有后端，不是新建后端。** `resolvePHPBinding` 先跑一次 `php.Discover()`，
  只接受本机探测到、且带 fpm 的版本；版本不存在或只有 cli/cgi 时返回 `ErrSitePHP`，
  写配置之前就失败。面板**不创建 per-site pool**，也不安装 PHP——那是 `php` 一项尚未交付的
 另一半。
* **vhost 里只多一个 handler 和一个 index。** `.php` location 固定为
  `try_files $uri =404;` + `include fastcgi_params;` + 显式
  `SCRIPT_FILENAME $document_root$fastcgi_script_name` + `fastcgi_pass unix:<socket>;`；
  index 改为 `index index.php index.html index.htm;`。socket 路径与版本写进
  `# minipanel-site:` 标记，删除站点或升级旧配置时随标记一起读回。
* **写纪律不变。** `SetPHP` 与创建站点一样走"写配置 → `nginx -t` → 通过才 reload"，
  任一步失败恢复上一份文件；证书操作重渲染时也会保留 PHP 绑定。
* **能力位图的分工。** `php_version_switch` 只在"站点写入可用 + 探测到带 fpm 的版本"时
  `available`；`php_fpm_versions` 只列带 fpm 的版本，是页面选择器的唯一来源。
  清空绑定（`php_version` 为空）是救援路径，不受该能力位图拦截。
* **不把 socket 存在说成后端可用。** 站点行上的 `php_socket_state` 是 `internal/php`
  对 `/proc/net/unix` 的现场读；`listening` 才表示此刻有进程在听，其余状态页面明说
  "站点会 502"。绑定成功不等于 PHP 能跑。

API：创建站点时请求体可带 `php_version`；已有站点用
`PUT /api/v1/sites/{name}/php`，`{"php_version": "8.3"}` 切换、空串清空。
能力不可用时选择版本返回 `403 capability`，清空仍放行；版本无效或没有 fpm 返回
`422 php_unavailable`。

### §5.6 站点基础设置编辑（M2 第七片落地）

这一节描述"改一个已存在站点"的边界。它只替换三样操作者数据：域名列表、文档根目录、
默认文档列表；站点名、PHP 绑定与证书文件都不动。

* **全量替换，不是补丁。** `PUT /api/v1/sites/{name}` 的请求体是
  `{domains[], root?, index?}`。`domains` 必须给全（1-20 个，和创建同一套主机名校验与去重）；
  `root` 省略或为空表示保留当前目录；`index` 省略或为空表示恢复内置列表
  （绑定 PHP 时 `index.php index.html index.htm`，否则 `index.html index.htm`）。
* **默认文档是文件名，不是路径。** `validateIndex` 只接受 1-64 位字母/数字/点/下划线/连字符、
  最多 10 项，拒绝 `..` 与任何路径分隔符；未绑定 PHP 时拒绝 `.php` / `.phtml` / `.phar` 项——
  nginx 会把它们当普通文本返回，等于把源码交给访客。绑定 PHP 的站点可以选择 `index.php`；
  反过来，**清空 PHP 绑定前必须先把这个自定义项改掉**，`SetPHP` 会拒绝让静态站点继承它。
* **证书覆盖先于写入。** 域名变更且 `TLS != nil` 时，`SetBasics` 从 `CertDir` 读回现有证书与私钥，
  用 `validateCertificate` 对新域名集合重新校验。覆盖不了就返回 `ErrTLSInvalid`（API 为
  422 `invalid_tls`），配置文件一个字节都不写；缩窄到证书已覆盖的子集则允许。这样不会出现
  "vhost 声明了 new.example.com、`ssl_certificate` 还是 old.example.com"的错配。需要换名字时，
  先关闭 HTTPS、编辑域名，再重新签发或上传。
* **根目录创建与回滚。** 新根目录不存在时以 0755 创建；随后的 `nginx -t` 或 reload 失败，
  `applyConfig` 先恢复上一份配置，调用方再删除刚建的空目录。旧根目录及其内容从不移动、不删除
  ——改配置不是搬数据。
* **写纪律不变。** 仍然走"写配置 → `nginx -t` → 通过才 reload"；`render` 重写 vhost 时保留
  TLS 与 PHP 字段，`SetBasics` 成功后返回的站点行含新的 `domains` / `root` / `index`。
  `index` 写进 `# minipanel-site:` 标记，页面下次读取时原样回填。

API：`PUT /api/v1/sites/{name}`；成功 200 + 站点行，参数不合法 400 `invalid_site`，
证书覆盖不了 422 `invalid_tls`，nginx 拒绝 422 `nginx_rejected`，站点不存在 404 `not_found`。

### §5.7 站点伪静态模板（M2 第八片落地）

这一节描述"给站点选一套重写规则"的边界。它是**封闭模板集**，不是一个可以填任意 nginx
指令的配置编辑器；`site_write` 的语义仍然只是"改面板自己写出的 vhost"。

* **模板 ID 是词汇表，不是内容。** `GET /api/v1/sites/rewrite-presets` 返回五项：
  `none`（默认 `try_files $uri $uri/ =404`）、`wordpress`、`laravel`、`thinkphp`、`spa`。
  `PUT /api/v1/sites/{name}/rewrite` 的请求体只有 `{preset}`；服务端 `validateRewrite`
  拒绝未知 ID，`rewriteLocation` 把它映射为固定的 `try_files` 片段。调用方提交的任何配置文本
  都没有入口——这既挡住了注入，也保证页面选项与后端白名单不会漂移（列表本身也由后端提供）。
* **PHP 依赖是双向的。** `wordpress` / `laravel` / `thinkphp` 的回退目标是 `/index.php`，
  因此 `RequiresPHP` 为真：静态站点选它们返回 400 `invalid_site`；反过来，站点正在使用这些
  模板时 `SetPHP` 拒绝清空 PHP，必须先切回 `none` 或 `spa`，否则 nginx 会把 `index.php`
  当普通文本返回，等于交出源码。`spa` 回退到 `/index.html`，纯静态站点可用。
* **写纪律不变。** `SetRewrite` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才 reload，
  任一步失败恢复原字节；模板 ID 写进 `# minipanel-site:` 标记，`List` 下次读取时原样回填。
  marker 里出现未知或不合法的 `rewrite` 值，该文件不会被当作面板站点（`foreign` 语义）。
* **范围。** 这一片不提供自定义规则、不下载第三方规则、不做按目录的局部重写；防盗链已随
  第十一片交付（§5.10，正则 location，不占用 `location /`，可与伪静态共存），目录访问密码等
  其它 `site_write` 子项仍未交付，仍以带理由的灰项呈现。反向代理已随第九片交付，
  整站跳转已随第十片交付，它们与伪静态互斥（§5.8、§5.9）。

API：`GET /api/v1/sites/rewrite-presets` 返回 `{items:[{id,label,description,requires_php}]}`；
`PUT /api/v1/sites/{name}/rewrite` 成功 200 + 站点行，未知模板 400 `invalid_site`，
站点不存在 404 `not_found`，nginx 拒绝 422 `nginx_rejected`。

### §5.8 站点反向代理（M2 第九片落地）

这一节描述"把一个站点整站转发到另一个上游"的边界。它是**单个上游 URL 的固定模板**，
不是一个可以填任意 `location` 或 `proxy_pass` 参数的配置编辑器。

* **输入只有一个 URL 和一个开关。** `PUT /api/v1/sites/{name}/proxy` 的请求体是
  `{target, websocket}`。服务端用 `url.Parse` 解析 target，再按 scheme / host / port / path
  重新拼出规范化结果：只接受 `http` / `https`；主机名按 DNS 标签校验，IP 字面量交给
  `net.ParseIP`；端口限定 1-65535；路径只允许受限字符集且拒绝 `..`。userinfo、查询串、
  片段、控制字符以及 `; { }` 引号反斜杠 `$` 反引号等 nginx 元字符一律拒绝——调用方不能借
  URL 注入指令。长度上限 255 字节。
* **生成的指令是固定的。** `proxy_pass <target>;` 加 `proxy_http_version 1.1;` 与
  Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto 四个头；`websocket=true` 时再追加
  `Upgrade` 与 `Connection "upgrade"` 两行。没有 header 改写、路径重写、超时、缓冲或缓存
  参数入口；响应缓存随第廿五片交付（§5.25）：三个带边界的数字与开关，指令块固定，
  只缓存 GET/HEAD 的 200/302，301 有意不缓存。
* **清除代理始终允许。** `target` 为空字符串表示删除代理块，`location /` 回到默认的
  `try_files $uri $uri/ =404`。这是救援路径，不受任何额外前置条件拦截；但 `websocket=true`
  配空 target 返回 400 `invalid_site`，避免表单误操作留下"只有升级头"的怪状态。
* **与伪静态、整站跳转互斥。** 三者都写 `location /`，因此 `SetProxy` 在站点使用非 `none`
  模板或正在整站跳转时拒绝；`SetRewrite` / `SetRedirect` 在站点已启用代理时同样拒绝；
  `parseMarker` 遇到同时带多种所有者的文件，不把它当作面板站点。先把一边清空再启用另一边
  （整站跳转见 §5.9）。PHP 绑定不受影响：`.php` 是正则 location，优先于 `location /`，可以与代理共存。
* **写纪律不变。** `SetProxy` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才 reload，
  任一步失败恢复原字节；代理目标与 WebSocket 布尔值写进 `# minipanel-site:` 标记，
  `List` 下次读取时原样回填。marker 里的 target 会重新走一遍同样的校验。
* **范围。** 多上游负载均衡随第二十片交付（§5.19）：它与单目标互斥，保存一边在同一次
  事务里清掉另一边。健康检查、多 location 分别代理、header 增删改、WebSocket 之外的协议
  升级与"代理到 unix socket"仍不提供，以带理由的灰项呈现。

API：`PUT /api/v1/sites/{name}/proxy` 成功 200 + 站点行；target 不合法或与伪静态冲突
400 `invalid_site`；站点不存在 404 `not_found`；nginx 拒绝 422 `nginx_rejected`。

### §5.9 站点整站跳转（M2 第十片落地）

这一节描述"把一个站点整站跳到另一个地址"的边界。它是**单个绝对 URL 与固定 `return` 行**，
不是可以填任意 `rewrite` / `if` / 正则的配置编辑器。

* **输入是一个 URL、一个状态码和一个开关。** `PUT /api/v1/sites/{name}/redirect` 的请求体是
  `{target, code, keep_path}`。target 与反向代理共用 `parseUpstreamURL`
  （`internal/nginx/proxy.go:54`）：`url.Parse` 后按 scheme / host / port / path 重新拼出
  规范化结果，只接受 `http` / `https`，拒绝 userinfo、查询串、片段、控制字符与 nginx 元字符，
  长度上限 255 字节。非空 target 时状态码必填，只接受 301 或 302；0、307、308 等其余值
  一律 400 `invalid_site`。清除跳转时状态码与保留路径一并忽略。
* **生成的指令只有一行。** `return <code> <target>;`；`keep_path=true` 时变成
  `return <code> <target>$request_uri;`。目标尾部斜杠在拼接前去掉，避免 `//a/b`。
  没有 flags（`last` / `break`）、没有正则、没有条件、没有按路径分别跳转的入口。
* **清除跳转始终允许。** `target` 为空字符串表示删除 `return` 行，`location /` 回到默认的
  `try_files $uri $uri/ =404`。这是救援路径；此时 `code` 与 `keep_path` 一并忽略，
  避免表单残留值阻止清除。
* **与伪静态、反向代理三者互斥。** 它们都写 `location /`，因此四处强制：`SetRedirect`
  在站点使用非 `none` 模板或已启用代理时拒绝；`SetProxy` 在站点正在跳转时拒绝非空 target；
  `SetRewrite` 在站点正在跳转时拒绝非 `none` 模板；`parseMarker` 遇到同时带多种所有者的
  文件（`proxy` / `redirect` / 非 `none` 模板计数大于 1），不把它当作面板站点。
  先把一边清空再启用另一边。PHP 绑定不受影响：`.php` 是正则 location，优先于 `location /`。
* **写纪律不变。** `SetRedirect` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才
  reload，任一步失败恢复原字节；目标、状态码与保留路径写进 `# minipanel-site:` 标记，
  `List` 下次读取时原样回填。marker 里的跳转字段会重新走一遍同样的校验，非法值使文件
  落到 `foreign` 语义而不会被列出。
* **范围。** 本节只负责整站跳转，不在这里按路径分别配置；精确路径例外是第十四片的
  独立功能（§5.13）。正则匹配、307/308、跳转到相对路径或内部 location 仍未交付，
  以带理由的灰项呈现。

API：`PUT /api/v1/sites/{name}/redirect` 成功 200 + 站点行；target / code 不合法或与伪静态、
反向代理冲突 400 `invalid_site`；站点不存在 404 `not_found`；nginx 拒绝 422 `nginx_rejected`。

### §5.10 站点防盗链（M2 第十一片落地）

这一节描述"拒绝站外页面直接引用本站静态资源"的边界。它是**固定的 Referer 校验块**，
不是可以填任意 `valid_referers` 参数或自定义规则的配置编辑器。

* **输入只有两个开关。** `PUT /api/v1/sites/{name}/hotlink` 的请求体是
  `{enabled, allow_empty}`。`enabled=false` 表示删除校验块，是始终允许的关闭路径；
  `allow_empty=true` 时写入 `valid_referers none blocked server_names;`，放行地址栏、
  命令行与隐私浏览器的无 Referer 请求；false 时只写 `server_names`，其它来源一律 403。
* **扩展名与指令都是后端常量。** 受保护的是图片、字体、样式、脚本与音视频扩展名：
  `jpg jpeg png gif webp avif svg ico bmp css js mjs woff woff2 ttf otf eot mp4 webm mp3 ogg oga wav`。
  生成的块是固定的 `location ~* \.(…)$`，里面只有 `valid_referers` 与
  `if ($invalid_referer) { return 403; }`；没有自定义域名白名单、状态码、日志开关或按路径的
  例外规则。新增扩展名必须改代码与测试，页面不能输入。
* **它不占用 `location /`。** 这是一个正则 location，nginx 会先于前缀 location 匹配，
  因此可与伪静态模板、PHP 绑定共存；`SetHotlink` 不检查这两者，`SetRewrite` / `SetPHP`
  也不因防盗链而拒绝。反过来，反向代理与整站跳转会把请求交给上游或直接返回跳转，
  本机静态资源块不可达，所以 `SetHotlink` 在站点已启用二者时拒绝，`SetProxy` /
  `SetRedirect` 在站点已启用防盗链时同样拒绝；`parseMarker` 遇到同时带
  `hotlink` 与 `proxy` / `redirect` 的文件，不把它当作面板站点。
* **写纪律不变。** `SetHotlink` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才
  reload，任一步失败恢复原字节；`enabled` 与 `allow_empty` 写进 `# minipanel-site:` 标记，
  `List` 下次读取时原样回填。孤立或矛盾的 marker 字段会被归一化：`allow_empty` 在
  `enabled=false` 时强制为 false。非法组合使文件落到 `foreign` 语义。
* **范围与局限。** Referer 只是浏览器自愿发送的头，伪造或剥离它都能绕过；本片不提供
  token 签名 URL、按域名 / IP 的精细白名单、防盗链命中日志或自定义响应页。它的定位是
  "挡住常见的站外盗链"，不是访问控制。目录访问密码随第十二片交付（§5.11）；
  真实 IP 解析随第十三片交付（§5.12）；按路径的精确跳转表随第十四片交付（§5.13），
  token 签名 URL、按域名 / IP 的精细白名单与防盗链命中日志等其它子项仍未交付。

API：`PUT /api/v1/sites/{name}/hotlink` 成功 200 + 站点行；与反向代理 / 整站跳转冲突
400 `invalid_site`；站点不存在 404 `not_found`；nginx 拒绝 422 `nginx_rejected`。

### §5.11 站点访问密码（M2 第十二片落地）

这一节描述"打开站点先要用户名口令"的边界。它是**固定的 HTTP Basic Auth 整站门**，
不是 htpasswd 管理器，也不是按目录 / 按路径的权限系统。

* **输入只有一对凭据。** `PUT /api/v1/sites/{name}/auth` 的请求体是
  `{username, password}`。用户名限 1-32 位字母、数字、点、下划线或连字符（首字符为字母或
  数字），口令 8-128 个字符且不含控制字符。用户名与口令同时为空表示关闭；只给其中一项
  返回 400，不会被解释成"保留原值"。
* **口令只以摘要落盘。** 后端写入 `username:{SHA}base64(SHA-1(password))`，
  文件在 `/etc/minipanel/auth/minipanel-<name>.htpasswd`，目录 0700、文件 0600。
  vhost 里只有两条固定指令：`auth_basic "Mini Panel";` 与
  `auth_basic_user_file <路径>;`；realm、路径和摘要格式都由面板决定，调用方不能提交
  任何配置文本。响应、审计参数与 marker 都不含口令或摘要——marker 只记 `auth_user`。
* **整站生效，不占 `location /`。** 两条指令写在 server 级，所以与伪静态模板、反向代理、
  整站跳转、防盗链和 PHP 绑定全部共存，不需要任何互斥规则；代理的上游、跳转的目标与
  静态资源块都照常工作，只是进入前先要凭据。关闭（两项都空）是始终允许的救援路径，
  配置更新成功后才删除口令文件；失败时口令文件保持原样。
* **ACME 例外。** 站点已启用 HTTPS 时，渲染追加一个
  `location ^~ /.well-known/acme-challenge/ { auth_basic off; ... }`；HTTP-01 校验不带
  凭据、走 80 端口，没有这条例外，证书到期续期会被 401 挡成失败。80 端口跳转块本来就没有
  口令门，因此重定向模式下 challenge 也是公开的。
* **写纪律不变。** `SetAuth` 走同一条 `applyConfig`：写配置 → `nginx -t` → 通过才
  reload，任一失败恢复配置原字节；口令文件在写配置前落盘，失败时按旧内容恢复或删除
  （原本不存在时），所以不会留下"配置指向一个不存在的口令文件"的状态。只改口令不改变
  vhost，`applyConfig` 判定无变化即返回成功，不触发 reload——口令文件是每次请求读取的。
* **范围与局限。** 只有一个用户、整站生效；没有用户组、按路径 / 目录的口令、
  自定义 401 页面、防爆破计数或口令轮换提醒。`{SHA}` 是无盐快速摘要，文件泄露后可以
  离线快速尝试，它的定位是挡住随手访问，不是强口令存储；这条限制写在接口描述与页面上，
  而不是留给用户猜。

API：`PUT /api/v1/sites/{name}/auth` 成功 200 + 站点行（含 `auth_user`，不含口令）；
用户名 / 口令不合法 400 `invalid_site`；站点不存在 404 `not_found`；
nginx 拒绝 422 `nginx_rejected`。

### §5.12 站点真实 IP 解析（M2 第十三片落地）

这一节描述"站点在 CDN / 反向代理后面时，怎样把日志里的来源地址还原成客户端地址"。
它是**固定的可信代理解析**，不是 GeoIP，也不是按 IP 的访问控制。

* **只有显式列出的对端才被信任。** `PUT /api/v1/sites/{name}/realip` 的请求体是
  `{from, header}`。`from` 是可信代理的 IP 或 CIDR 列表（最多 16 条，重复项去重），
  `header` 只能是 `X-Forwarded-For` 或 `X-Real-IP`，留空默认前者。后端拒绝
  `0.0.0.0/0`、`::/0` 与 `0.0.0.0` / `::`：那等于让任何客户端都能伪造来源地址。
  只给 `header` 不给 `from` 返回 400；两项都空表示关闭。
* **指令形状固定。** 每个可信来源写一条 `set_real_ip_from <IP 或 CIDR>;`，再写一条
  `real_ip_header <名称>;`；`X-Forwarded-For` 额外写 `real_ip_recursive on`，
  `X-Real-IP` 不写（nginx 对它不使用递归开关）。调用方不能提交任何配置文本，
  地址会先规范成 IP 或网络形式（例如 `10.1.2.3/8` 写成 `10.0.0.0/8`）再落盘。
* **server 级、与其它站点功能共存。** 它不占用 `location /`，因此与伪静态模板、
  反向代理、整站跳转、防盗链、访问密码和 PHP 绑定全部共存，不需要互斥规则。
  它影响的是该 vhost 的 `$remote_addr`、访问日志与后续按 IP 的规则，不改变面板自身
  的来源判断（面板的 `clientIP()` 另有 `panel.trust_proxy` 开关，默认关闭）。
* **关闭与回滚。** `from` 为空且 `header` 为空时删除整段指令；这是始终允许的救援路径。
  写配置仍走"写配置 → `nginx -t` → 通过才 reload"，失败恢复配置原字节。
* **范围与局限。** 没有 GeoIP、国家/地区规则、按 IP 的站点白名单或黑名单；也不校验
  转发头里的地址是否真实。可信代理本身必须负责剥掉客户端自带的同名请求头，否则
  列表内的代理仍然会把伪造值传进来——这条限制写在接口描述与页面上。

API：`PUT /api/v1/sites/{name}/realip` 成功 200 + 站点行（含 `real_ip_from` 与
`real_ip_header`）；地址、网段或请求头不合法 400 `invalid_site`；站点不存在 404
`not_found`；nginx 拒绝 422 `nginx_rejected`。

### §5.13 站点按路径跳转表（M2 第十四片落地）

这一节描述"站点里少数精确路径跳到别处，其余请求仍走原来的静态、代理、伪静态或整站跳转"的边界。
它是**固定模板表**，不是 nginx 配置编辑器。

* **输入是一张表。** `PUT /api/v1/sites/{name}/redirect-paths` 的请求体是
  `{rules:[{path,target,code}]}`。`path` 必须以 `/` 开头，只允许字母、数字与
  `. _ ~ / -`，总长不超过 128 个字符；请求区分大小写，面板不会擅自把
  `/Old` 改成 `/old`。尾部斜杠归一化后不能变成站点根路径，不能包含 `..`，也不能以
  `/.well-known/acme-challenge` 开头遮蔽证书校验。最多 10 条，重复路径拒绝。
* **目标沿用整站跳转的 URL 规则。** 每条 `target` 都经过 `parseUpstreamURL`
  （`internal/nginx/proxy.go:54 parseUpstreamURL()`）规范化，只接受绝对
  `http` / `https` URL，拒绝 userinfo、查询串、片段、控制字符与 nginx 元字符；
  `code` 只接受 301 或 302。调用方提交的任何字符都不会被当作 nginx 指令原文执行。
* **渲染形状固定。** 每条规则生成：
  `location = <path> { return <code> <target>$is_args$args; }`
  （`internal/nginx/pathredirect.go:78 redirectPathLocations()`）。这些是精确匹配例外，
  nginx 会先于 `location /` 处理，所以它们不接管站点根路径，也不会破坏原有整站跳转、
  反向代理、伪静态、静态资源、访问密码或 PHP 绑定。
* **整表替换与清除。** `rules` 是整张表的替代值；空数组清除所有路径例外。面板不维护增量
  ID，也不把一次点击拆成多条请求，因此不会出现"加了一条、删了一条，中间状态互相覆盖"的
  并发歧义。写配置仍走"写配置 → `nginx -t` → 通过才 reload"，失败恢复原字节
  （`internal/nginx/pathredirect.go:92 SetRedirectPaths()`）。
* **marker 与响应。** 规范化后的表写进站点标记（`internal/nginx/nginx.go:332`），读取回填到
  `redirect_paths`；非法表让文件落到 `foreign` 语义，而不是把未经校验的配置继续当成面板站点。
* **范围。** 只支持精确路径的 301/302，不支持正则、前缀通配、条件跳转、307/308、
  相对目标或跳转到内部 named location。按路径的响应头与缓存控制不在这一片；按路径的
  流量限制也不在这一片，整站级限速是第十五片的独立功能（§5.14）。

API：`PUT /api/v1/sites/{name}/redirect-paths` 成功 200 + 更新后的站点行；路径、目标、
状态码或数量不合法 400 `invalid_site`；站点不存在 404 `not_found`；nginx 拒绝 422
`nginx_rejected`。

### §5.14 站点流量限制（M2 第十五片落地）

这一节描述"限制单个客户端 IP 打到某个站点的请求速率与并发连接数"的边界。它是
**四个数值字段的表单**，不是 nginx 限速指令编辑器；难点在于 nginx 要求限速所用的
共享内存区（zone）定义在 `http` 上下文、而不是任何 `server` 块里，而面板按所有权模型
只拥有站点 vhost。这一片把这两个位置一起写，且用同一套"先测试后生效"纪律。

* **输入是四个值。** `PUT /api/v1/sites/{name}/traffic-limit` 的请求体是
  `{request_rate, burst, connections, status}`，四者全部留空（或省略）表示清除本站限流。
  `request_rate` 只接受 `10r/s`、`200r/m`、`100r` 这类形状（数值 1-1000000，
  `internal/nginx/limits.go:79 normalizeTrafficLimit()`），先归一化再落配置；`connections`
  是单 IP 并发连接上限（0-100000）；速率与连接数至少给一个，否则 `burst` 与 `status`
  没有作用，返回 400。`burst`（0-100000）只在设置了速率时被接受；`status` 只接受 429 与
  503，留空沿用 nginx 默认的 503。
* **vhost 里的指令是固定的。** 面板按站点名派生 zone 名（`internal/nginx/limits.go:124
  limitZoneName()`：`mp_` 前缀、连字符换成下划线，站点名字符集保证映射不碰撞），渲染
  server 级的 `limit_req zone=<名>_req [burst=N nodelay]`、`limit_conn <名>_conn N`
  与可选的 `limit_req_status` / `limit_conn_status`（`internal/nginx/limits.go:131
  trafficLimitLines()`，写进 `internal/nginx/tls.go:480`）。键固定
  `$binary_remote_addr`、zone 大小固定 10m，调用方不能提交任何配置文本或自定义 zone 名。
* **zone 定义落在 http 上下文，与 vhost 同一次事务落盘。** `limit_req_zone` /
  `limit_conn_zone` 必须在 `server` 块之外，所以面板另写一张自己拥有的表文件
  （`internal/nginx/limits.go:166 renderLimits()`），位置由本机 `nginx.conf` 里已存在的
  通配 include 决定（`internal/nginx/limits.go:235 httpIncludeDirs()` → `internal/nginx/limits.go:287 limitsPath()`），
  Debian 布局落在 `sites-enabled/*`、RHEL/OpenResty 落在 `conf.d/*.conf`；表文件名不带点，
  避免被 `*` 与 `*.conf` 两条 glob 各包含一次而重复定义 zone。一次限流改动通过
  `internal/nginx/nginx.go:946 configFile` + `internal/nginx/limits.go:355 applyFiles()`
  把 vhost 与表文件放进同一条"写文件 → `nginx -t` → 通过才 reload"事务，任一步失败
  两个文件都恢复原字节（表原本不存在则删除）。
* **整表随站点列表重建，绝不留悬空 zone。** 表内容来自当前所有面板站点里带限流的那些
  （`internal/nginx/limits.go:442 limitsRows()`），不是请求里的片段：清除一个站点、删除一个
  站点都会整表重写，因此不可能出现"vhost 引用了一个表里没有的 zone"——那正是 nginx
  拒绝启动的配置形状。最后一个限流消失时表文件被删除（空文件在 `include conf.d/*.conf`
  下无法作为 http 级配置解析）。表文件若同名但不是面板写的（`internal/nginx/limits.go:197
  parseLimitsMarker()`），写入被拒绝，不改别人的文件。
* **本机没有 http 级通配 include 时明确拒绝。** 面板不猜测一个无法确认会被 nginx 读取的
  位置，直接返回带理由的 400 `invalid_site`；没有任何限流站点的宿主不受这条影响，其它站点
  写操作照常。
* **marker 与共存。** 归一化后的限流写进站点标记（`internal/nginx/nginx.go:334`），读取时
  经 `internal/nginx/limits.go:211 limitsFromMarker()` 回填 `limits`，非法值让文件落到
  `foreign` 语义。限流是 server 级指令、不占用 `location /`，因此与静态、伪静态、反向代理、
  整站跳转、按路径跳转、防盗链、访问密码、真实 IP 与 PHP 绑定全部共存。

API：`PUT /api/v1/sites/{name}/traffic-limit` 成功 200 + 站点行（含 `limits`）；速率、
突发、连接数、状态码不合法或本机没有可用 include 400 `invalid_site`；站点不存在 404
`not_found`；nginx 拒绝 422 `nginx_rejected`（vhost 与 zone 表一起回滚）；平台 Provider
未实现 `SiteTrafficLimitManager` 时 403 `capability`。

### §5.15 站点分组 / 备注 / 搜索（M2 第十六片落地）

这是站点侧唯一一项**不写 nginx 配置**的能力。前面每一片（PHP 绑定、伪静态、代理、跳转、防盗
链、访问密码、真实 IP、按路径跳转、流量限制）都往 `internal/platform/sites.go` 加一个 `Set*`
可选接口，因为它们各自都要改一份配置、跑一次 `nginx -t`、失败回滚。分组与备注改的不是配置，
是面板自己的数据，所以这一片刻意不加 Provider 接口，落点上移到 store + HTTP 层：

* **存哪里。** `internal/store/store.go:244` 把 schema 从 v3 升到 v4，`internal/store/store.go:254` 建一张 `site_meta`
  表（`name` 主键 + `grp` + `note` + `updated_at`）。`internal/store/store.go:502 SiteMeta` 是它的
  中立形状，读写各一个方法：`internal/store/store.go:510 ListSiteMeta()`（全表，列表 join 用）、
  `internal/store/store.go:531 SaveSiteMeta()`（upsert；两项都空时走 DELETE 分支，不留空行）、
  `internal/store/store.go:546 DeleteSiteMeta()`（删站点时清行）。迁移可重入，`CREATE TABLE IF NOT
  EXISTS` 让重复 migrate 安全，与前面每一版迁移同一口径。
* **谁填 group/note。** 不是 Provider——`internal/platform/sites.go:106` `Group` / `internal/platform/sites.go:107` `Note` 两个
  字段在 `toSiteInfo` 里永远是空的（nginx 不知道它们存在）。只有 `internal/api/sites.go:350 mergeSiteMeta()`
  在 `internal/api/sites.go:364 handleSitesList()` 读列表时按站点名把它们 join 回去。因此任何
  单站点写操作（切 PHP、设限流等）的响应里 group/note 都是空，页面在这些操作后统一重新拉列表
  刷新，而不是拿一条不含标注的行去覆盖已有行。
* **诚实性红线换了地方。** 写入类片子的红线是"不写 nginx 会拒的配置、失败回滚"；这里没有配置
  可回滚，红线变成**存在性**：`internal/api/sites.go:1181 handleSiteMeta()` 在落库前先拿 Provider 的
  `List()` 核对站点名，对不在列表里的名字返回 404 `not_found`，绝不给一个 nginx 里根本没有的站点
  凭空记一行分组。校验由 `internal/api/sites.go:324 normalizeSiteMeta()` 完成：group 单行 ≤64 字符、
  禁止任何控制字符；note ≤500 字符、可换行但禁止除 `\n`/`\t` 外的控制字符；两项同时为空是清除路径。
  它复用 `siteManager()` 这道 `site` 能力闸门——列不出站点的平台（Windows、无 nginx、非 root）同样
  在这里返回带理由的 403，而不是默默存一行没人会看到的标注。
* **删除与残留。** `internal/api/sites.go:1145 handleSiteDelete()` 在 Provider 删除成功后 best-effort
  调 `DeleteSiteMeta` 清行（`internal/api/server.go:148` 是 `/sites/{name}/meta` 的路由注册点）。即使
  清理失败，列表 join 只认 Provider 现报的站点，残留行也永不显示——这一点和流量限制"整表重建不留
  悬空 zone"是同一种"宁可不显示也不显示错的"纪律。
* **搜索与分组过滤在前端。** 页面拿到的已是带 group/note 的完整列表，搜索框对 name、域名、分组、
  备注拼成的串做不区分大小写的子串匹配，分组下拉精确匹配 `group`，都在已加载列表上即时过滤，不再
  多打一次后端。这不是偷懒：分组与备注本来就只在面板数据库里，后端分页搜索反而要为此维护一份与
  nginx 文件系统列表不一致的第二真相。

API：`PUT /api/v1/sites/{name}/meta`（`internal/api/openapi/panel.yaml:1071`）成功 200 + 带 group/note
的站点行；group/note 超长或含控制字符 400 `invalid_site`；站点不是 Provider 管理的 404 `not_found`；
`site` 能力不可用 403 `capability`；缺 CSRF 403。它**没有** 422，因为没有任何 nginx 写入会失败。
范围边界：一个站点至多一个分组、无分组权限、无按分组批量操作、备注是纯文本不是富文本或附件。

### §5.16 站点目录列表 / 强制 HTTPS 开关（M2 第十七片落地）

宝塔的站点设置里有两处是"一个开关、一条固定指令"级别的：目录列表（autoindex）与强制 HTTPS
跳转。这一片把它们做进来，形态与前面所有写入类片子相同——调用方只给布尔值，指令是面板常量，
**不接受任何配置文本**，写入仍走 render → `nginx -t` → 通过才 reload → 失败恢复原字节。

* **目录列表**：`PUT /api/v1/sites/{name}/autoindex` 接受 `{enabled}`，`internal/nginx/behavior.go:18 SetAutoIndex()`
  翻转 `Site.AutoIndex`（`internal/nginx/nginx.go:273`），`internal/nginx/tls.go:445` 在 index 分流后写死
  `autoindex on;`。它是 server 级指令、不占用 `location /`，因此与静态、伪静态、代理、整站/按路径
  跳转、防盗链、访问密码、真实 IP、流量限制全部共存；关闭（`enabled=false`）是始终允许的路径。
  `autoindex` 写进 marker（`internal/nginx/nginx.go:338`）、`readSite`（`internal/nginx/nginx.go:555`）回填、`render`（`internal/nginx/nginx.go:1106`）往返，
  `List` 原样显示当前状态。
* **强制 HTTPS**：`PUT /api/v1/sites/{name}/force-https` 接受 `{enabled}`，`internal/nginx/behavior.go:41 SetForceHTTPS()`
  翻转的就是证书接口早已写进 marker 的 `TLS.Redirect`——这一片**不新增第二真相**，只多读一个已有布尔。
  因此它有一条诚实性红线：站点没启用 HTTPS（`TLS==nil || !TLS.Enabled`）时请求开启，被
  `SetForceHTTPS` 以 `ErrInvalid` 挡回，HTTP 侧映射为 400 `invalid_site`，绝不静默生成一段指向不存在证书的
  301；未启用 HTTPS 的站点请求关闭则是无副作用的成功（no-op）。`renderRedirect`（`internal/nginx/tls.go:389`）
  据此产出端口 80 的 `return 301 https://$host$request_uri;` 跳转块，并为 ACME 保留 `/.well-known/acme-challenge/`。
* **门槛沿用 site 能力，不新增能力位**：`internal/api/sites.go:292 siteBehaviorManager()` 调 `s.siteManager()`
  再类型断言 `platform.SiteBehaviorManager`（`internal/platform/sites.go:365`）；Provider 没实现这两个方法时
  返回 403 `{"kind":"capability"}`，页面据此显示"这台没实现"的理由。Linux 适配在
  `internal/platform/platform_linux.go:427 SetAutoIndex()` / `internal/platform/platform_linux.go:439 SetForceHTTPS()`，接口断言在 `internal/platform/platform_linux.go:52`。

范围边界：不提供 autoindex 的格式（`autoindex_exactsize` / fancyindex 模板）与按目录范围控制；不为
强制 HTTPS 单开能力位；这两处都只是布尔开关，不做 autoindex 根目录重定位之类的组合玩法。

### §5.17 站点日志查看器（M2 第十八片落地）

宝塔的站点日志是"按站点各一份 access/error 日志 + 页面看尾部"。这一片把它做全，形态上仍是
面板常量：日志指令、格式（nginx 内建 combined）、目录与文件名全部由后端决定，调用方只选
kind（access/error 闭集）与行数（1-500），**提交不了任何路径或配置文本**。

* **渲染**：每个面板自有 vhost 的主 server 块带 `access_log <LogDir>/<name>.access.log combined;`
  与 `error_log <LogDir>/<name>.error.log;`（`internal/nginx/logs.go:55 siteLogLines()`，
  `internal/nginx/tls.go:451`）；强制 HTTPS 的 80 端口跳转块同样带（`internal/nginx/tls.go:399`），
  否则开了强制 HTTPS 的站点全部流量走跳转块、按站点日志一条不写。日志路径与 `AuthFile` 同款，
  是派生的主机状态（`internal/nginx/nginx.go:283` `json:"-"`），不进 marker：渲染与读取共用
  `internal/nginx/logs.go:48 siteLogPath()`，篡改 marker 挪不动日志位置。
* **运行时前提**：本机 nginx 1.18 实测 `nginx -t` 对不存在的日志目录照样通过，reload 后才打不开
  日志。因此 `internal/nginx/logs.go:94 ensureLogDir()` 在每次配置事务写入前创建目录，root 运行时
  读本机 nginx.conf 的 `user` 指令（`internal/nginx/logs.go:65 nginxUser()`，缺省 nobody）把目录
  chown 给 worker；三个写入咽喉点都接了它（applyFiles `internal/nginx/limits.go:387`、
  writeConfig `internal/nginx/tls.go:248`、Create `internal/nginx/nginx.go:774`）。
* **迁移**：面板启动时 `cmd/minipanel/main.go:302 migrateSiteLogs()` 调
  `internal/nginx/logs.go:190 MigrateSiteLogs()`，把全部面板自有 vhost 的重新渲染放进**同一次**
  applyFiles 事务：一次 `nginx -t`、一次 reload、失败全部还原；外部 / 无 marker 文件不碰，
  全部已最新时零 reload。迁移失败只记警告不崩面板，站点照旧服务，查看器如实说文件不在。
* **查看**：`GET /api/v1/sites/{name}/logs`（`internal/api/sites.go:996 handleSiteLogs()`）先过
  `internal/api/sites.go:307 siteLogManager()` 门槛（Provider 未实现 `SiteLogManager` → 403
  capability 带理由），再经 readSite 核所有权；`internal/nginx/logs.go:123 ReadLog()` 只读最后
  1MB 窗口（`internal/nginx/logs.go:27 logTailWindow`）、丢弃窗口起点的半行、按行数截尾并给出
  truncated 标记。文件不存在返回 200 + `exists=false`，页面显示"尚无日志"，不假装空文件是成功。

范围边界：不做日志切割（M6 的 cron 任务对象）、不做实时 tail / WebSocket 推送、不接受自定义
日志路径或格式、不动外部 vhost 的日志配置；删站保留日志文件——日志与网站根目录一样是操作者数据。



### §5.18 站点自定义错误页（M2 第十九片落地）

宝塔的自定义错误页是"给 404/500 等状态各指一个站内页面"。这一片按同一形态落地，仍然是
面板常量：调用方只提交 `{code, path}` 结构表，后端渲染固定的 server 级 `error_page` 行，
**提交不了任何 nginx 配置文本**。

* **校验**：`internal/nginx/errorpage.go:41 normalizeErrorPages()` 只接受封闭状态码列表
  （`internal/nginx/errorpage.go:27 errorPageCodes`：400/401/403/404/405/408/500/502/503/504），
  重复状态码、超过 10 条都拒绝；路径必须以 / 开头、只允许字母数字与 `. _ ~ / -`
  （`internal/nginx/errorpage.go:22 errorPagePathRe`），拒绝 `..` 与 ACME challenge 前缀。
  同一套校验在 `internal/nginx/nginx.go:637` 的 parseMarker 里再次执行：坏 marker 让整个
  文件按外部处理，篡改标记不能把非法指令夹带进渲染。
* **渲染**：每条规则一行 `error_page <code> <path>;`（`internal/nginx/errorpage.go:77 errorPageLines()`，
  分流在 `internal/nginx/tls.go:453`），外加每个不同的错误页路径一个空的精确静态
  `location =` 块（`internal/nginx/errorpage.go:91 errorPageLocations()`，分流在
  `internal/nginx/tls.go:497`）。后者来自本机 nginx 1.18 的实测：error_page 的内部重定向
  会落进 `location /`，反代站点的错误页会被代理到可能已挂掉的上游——恰好在最需要它的
  时刻失效；精确块让它永远从站点根目录静态提供。它不占用 `location /`，与静态、伪静态、
  反向代理、整站/按路径跳转、防盗链、访问密码、真实 IP、目录列表、流量限制和 PHP 绑定
  全部共存；写入走 `internal/nginx/errorpage.go:126 SetErrorPages()` → applyConfig 的
  同一"写配置 → `nginx -t` → 通过才 reload"事务，失败恢复原字节。空表清除始终允许。
* **冲突互斥**：错误页路径与按路径跳转例外渲染同一个 `location =` token，nginx 拒绝重复
  定义，因此 `internal/nginx/errorpage.go:110 errorPagesCollide()` 在 `SetErrorPages`、
  `SetRedirectPaths`（`internal/nginx/pathredirect.go:104`）与 parseMarker
  （`internal/nginx/nginx.go:642`）三处把冲突挡成带理由的 400，而不是抛一个难懂的
  nginx -t 失败；坏 marker 同样让整个文件按外部处理。
* **HTTP**：`PUT /api/v1/sites/{name}/error-pages`（`internal/api/sites.go:711 handleSiteErrorPages()`）
  先过 `internal/api/sites.go:173 siteErrorPageManager()` 门槛（Provider 未实现
  `SiteErrorPageManager` → 403 capability 带理由），错误映射与兄弟端点一致：
  400 invalid_site / 404 not_found / 422 nginx_rejected。

范围边界（OpenAPI 与页面对话框原话写明）：`error_page` 只替换 nginx 本机产生的错误，
反代站点的上游错误响应原样透传，面板不开启 `proxy_intercept_errors`；错误页文件是操作者
数据，面板不代写 HTML，文件缺失时 nginx 回退内置错误页（或链到已配置的其他错误页）而不是
500——静态 404、反代死上游 502、文件缺失回退三条路径都在本机 nginx 1.18 实测过。不做按
location 的错误页、不做错误页文件编辑器、不做 `recursive_error_pages`。

### §5.19 站点反向代理多上游负载均衡（M2 第二十片落地）

宝塔的反向代理支持多个上游加权重与算法。这一片按同一形态落地，仍然是结构表：调用方只提交
`{upstreams:[{target,weight}], method, websocket}`，后端渲染固定的 `upstream` 块与
`proxy_pass`，**提交不了任何 nginx 配置文本**。

* **校验**：`internal/nginx/proxyupstream.go:61 normalizeProxyUpstreams()` 复用
  `internal/nginx/proxy.go:54 parseUpstreamURL()` 的字符白名单，再额外要求 scheme 为
  http、路径为空——nginx 的 `upstream server` 只接受 host:port，本片不做上游 TLS；
  同一 host:port 重复拒绝，最多 10 个（`internal/nginx/proxyupstream.go:18 maxProxyUpstreams`），
  权重 1-100、省略或 0 归一化为 1。算法是封闭列表
  （`internal/nginx/proxyupstream.go:38 proxyLBMethods`）：省略 / round_robin（归一化为
  省略，即 nginx 默认加权轮询）、ip_hash、least_conn。同一套校验在
  `internal/nginx/nginx.go:592` 的 parseMarker 里再次执行，坏 marker 让整个文件按外部处理。
* **渲染与 http 级前提**：vhost 的 `location /` 写 `proxy_pass http://<站点派生名>_upstream`
  （`internal/nginx/proxy.go:159` 分流，派生名 `internal/nginx/proxyupstream.go:107 upstreamName()`
  与限流 zone 同规则），upstream 块（method 指令 + 每后端一行 `server host:port [weight=N]`，
  `internal/nginx/proxyupstream.go:122 renderUpstreams()`）必须落在 http 上下文，因此复用
  第十五片限流 zone 表的整套机制：写进本机 nginx.conf 已存在通配 include 的目录
  （`internal/nginx/proxyupstream.go:165 upstreamsPath()`），每次改动按当前站点列表整表重建
  （`internal/nginx/proxyupstream.go:189 upstreamRows()`），最后一个 upstream 消失时删除
  表文件，外部同名文件拒绝接管（`internal/nginx/proxyupstream.go:152 parseUpstreamsMarker()`）。
  找不到通配 include 时带理由返回 400；单目标代理不依赖该前提，照常可用。
* **交接原子性**：单目标 `proxy_target` 与多上游表互斥（都占用 `location /`）。
  `internal/nginx/proxyupstream.go:223 SetProxyUpstreams()` 清掉单目标，
  `internal/nginx/proxy.go:187 SetProxy()` 清掉本表并同事务重建
  （`internal/nginx/proxy.go:213`）；`Delete` 同样连表重建
  （`internal/nginx/nginx.go:1039`）。vhost 与表文件在同一次 applyFiles 事务里
  写文件 → `nginx -t` → 通过才 reload，任一步失败两个文件一起恢复原字节。
  与伪静态、整站跳转、防盗链的互斥统一走 `internal/nginx/proxyupstream.go:100 proxyActive()`
  （`internal/nginx/rewrite.go:129` / `internal/nginx/redirect.go:72` / `internal/nginx/hotlink.go:43`）；
  PHP 绑定、按路径跳转、错误页、限流等不占用 `location /` 的功能不受影响。
* **HTTP**：`PUT /api/v1/sites/{name}/proxy-upstreams`
  （`internal/api/sites.go:576 handleSiteProxyUpstreams()`）先过
  `internal/api/sites.go:114 siteProxyLBManager()` 门槛（Provider 未实现
  `SiteProxyLBManager` → 403 capability 带理由），错误映射与兄弟端点一致：
  400 invalid_site / 404 not_found / 422 nginx_rejected。空表清除始终允许
  （websocket=true 配空表返回 400）。

范围边界（OpenAPI 与页面对话框原话写明）：上游健康沿用 nginx 的被动判定（fail_timeout 内
失败即暂离），面板不做主动健康检查、不假装能验证后端存活；不支持 https 上游、backup/down
标记、多 location 分别代理与 header 增删改。本机 nginx 1.18 实测：双后端轮询严格交替、
ip_hash 同客户端 IP 固定后端、权重 3:1 在 8 次请求中 6:2 分发、least_conn 生效、
单目标↔多上游交接与表文件删除、清除后回到默认静态查找均验证通过。

### §5.20 站点 CORS 跨域策略（M2 第廿一片落地）

宝塔的跨域设置是"允许的来源 + 方法 + 头 + 凭据"。这一片按同一形态落地，仍然是结构表：
调用方只提交 `{origins, methods, headers, credentials, max_age}`，后端渲染固定的
server 级 `add_header` 与一个 OPTIONS 短路，**提交不了任何 nginx 配置文本**。

* **校验**：`internal/nginx/cors.go:54 normalizeCors()` 的来源复用
  `internal/nginx/proxy.go:54 parseUpstreamURL()` 白名单并要求路径为空（精确
  `scheme://host[:port]`，最多 10 个、去重、排序）；`*` 只能单独出现，且与
  credentials 互斥——浏览器禁止该组合，后端直接 400 而不是写出一份浏览器必然拒绝
  的配置。方法是七方法闭集（`internal/nginx/cors.go:34 corsMethods`，省略默认
  GET/HEAD/POST）；请求头是 RFC token 形状（`internal/nginx/cors.go:29 corsHeaderTokenRe`，
  最多 20 个，省略反射预检的 Access-Control-Request-Headers）；max_age 0-86400。
  同一套校验在 `internal/nginx/nginx.go:645` 的 parseMarker 里再次执行，坏 marker
  让整个文件按外部处理；空 origins 归一为关闭。
* **渲染**：`internal/nginx/cors.go:137 corsLines()`（分流 `internal/nginx/tls.go:491`）
  输出全部带 `always` 的 server 级 `add_header`（错误响应也带 CORS 头），外加
  `if ($request_method = OPTIONS) { return 204; }`。精确来源用每来源一条
  `if ($http_origin = ...)` 写进 `$mp_cors_origin` 再回显，未列出的来源得不到
  Allow-Origin 头（nginx 跳过空值头）并附 `Vary: Origin`；不需要 http 级 map，
  不依赖通配 include。预检 204 继承 server 级头这一点在本机 nginx 1.18 实测确认。
* **共存与清除**：不占用 `location /`，与静态、伪静态、反代（单/多目标）、整站/按
  路径跳转、防盗链、访问密码、真实 IP、目录列表、限流、错误页和 PHP 绑定全部共存

  空 origins 清除始终允许；写入走 `internal/nginx/cors.go:183 SetCors()` →
  applyConfig 的同一"写配置 → `nginx -t` → 通过才 reload"事务，失败恢复原字节。
* **HTTP**：`PUT /api/v1/sites/{name}/cors`（`internal/api/sites.go:800 handleSiteCors()`）
  先过 `internal/api/sites.go:216 siteCorsManager()` 门槛（Provider 未实现

范围边界（OpenAPI 与页面对话框原话写明）：开启期间 OPTIONS 由本机直接回 204，预检

### §5.21 站点配置文件编辑器（M2 第廿二片落地）

宝塔的"配置文件"是直接打开 vhost 文本编辑。这一片按**守护编辑器**落地：能改的是
面板自有 vhost 的文本，不能改的是面板对事实的所有权。它不是文件管理器。

* **读**：`GET /api/v1/sites/{name}/config`（`internal/api/sites.go:742 handleSiteConfigGet()`）

  `{name, path, content}`——content 是磁盘原始字节，不按 marker 重新生成，操作者

* **守护写**：`PUT`（`internal/api/sites.go:765 handleSiteConfigPut()`，body

  `internal/platform/platform_linux.go:344 SetSiteConfig()`（断言
  `internal/platform/platform_linux.go:51`）。HTTP 门槛
  `internal/api/sites.go:187 siteConfigManager()`：Provider 未实现 → 403

范围边界（OpenAPI `internal/api/openapi/panel.yaml:760` 与页面对话框原话写明）：

### §5.23 站点停用/启用（M2 第廿三片落地）

`PUT /api/v1/sites/{name}/enabled`，请求体 `{enabled}`。这是宝塔站点列表的
停用按钮在面板里的对应物：**手动**停站/开站，到期自动停用维持 §8.2 的拒绝。

两种布局两种机制、同一份契约（`internal/nginx/enable.go:50 SetEnabled()`）：

* sites-available/sites-enabled：停用=摘除启用符号链接，启用=重建相对链接
  （`internal/nginx/enable.go:84 setEnabledLink()`）。vhost 文件原地不动，
  其它功能写入完全不受影响。
* conf.d（没有链接层）：停用=把 vhost 移入配置根下的 `minipanel-disabled/`
  停放目录，启用=移回（`internal/nginx/enable.go:112 setEnabledMove()`）。
  停放目录不被任何通配 include 列出；readSite 回退读它
  （`internal/nginx/nginx.go:524`），List 加扫它（`internal/nginx/nginx.go:499`），
  Enabled 就是"文件不在停放目录"（`internal/nginx/nginx.go:569`）。

边界写死：停用**不删除**配置、证书、密码文件或网站目录；停用站点仍出现在列表
（enabled=false，config_path 指向停放位置），其余功能页照常可编辑，写入落在
停放文件里、启用后生效；同名建站仍被停放文件占用而 409 拒绝
（`internal/nginx/nginx.go:744`）；删除停用站点连停放文件一起清
（`internal/nginx/nginx.go:994`）。切换到当前状态是无操作成功、零 nginx 命令；
真实切换走 `nginx -t` → 通过才 reload，失败把链接/文件精确还原
（`internal/nginx/enable.go:136 testReloadOr()`）。限流 zone 表与 upstream 表
保留停用站点的条目——zone/upstream 定义本身不服务请求，保留使启用时无需重建表。

验收：`internal/nginx/enable_test.go` 9 个用例钉两种布局的机制、幂等、回滚、
所有权与停用期间的编辑/建站/删除；`internal/api/sites_enabled_test.go` 4 个用例
钉 HTTP 契约；本机 nginx 1.18 两种布局实测停站后请求落回默认页、启用后恢复服务；
Playwright 实测停用 popconfirm→已停用标签→启用→恢复全链路，五档视口无溢出。


### §5.24 配置历史快照（M2 第廿四片落地，写协议层）

§5.2 的承诺兑现：快照不等 M6，从 M2 起就是写协议的一部分。落地形态与
§5.2 的设计一致——`<DataDir>/config-history/<对象>/<时间戳>/` 存改前字节
（body）+ 元数据（meta.json：绝对路径、UTC 时间、SHA-256、字节数、是否
存在）。对象是配置文件名，时间戳带纳秒，固定时钟或同刻两次写入用序号后缀
区分，绝不覆盖已有快照（`internal/nginx/history.go:53 snapshotHistory()`）。

四个写入咽喉点全部接上：applyFiles 事务（`internal/nginx/limits.go:391`，
覆盖站点功能写、删站、限流/upstream 表重建）、TLS 路径的 writeConfig
（`internal/nginx/tls.go:251`）、Create 直写（`internal/nginx/nginx.go:778`，
记录"文件不存在"）、conf.d 停用/启用的文件移动（`internal/nginx/enable.go:119`）。

与 §5.2 原文的两处偏差，都是向更诚实的方向：actor 与 params_hash 不写进
快照元数据——每次面板写入都经过 auditWrites，同一时刻的审计条目已经携带
它们，重复存储就是第二个可能漂移的真相来源；"回滚的回滚"死循环由每对象
50 份的深度上限（`internal/nginx/history.go:39 historyKeep`）直接截断。
新增一条 §5.2 没有明说的红线：**快照写不进去就拒绝这次写入**——历史目录
不可写时配置变更整个不做，而不是照写然后声称可回滚。

无变更写入零快照；事务失败回滚后快照仍在（持久层不依赖事务成功）；站点
删除后其历史目录保留（历史是面板数据，不是站点数据）。版本列表/两版差异/
回滚到指定版本的 UI 与端点仍归 M4，本片不新增端点、能力位图不变。
验收：`internal/nginx/history_test.go` 8 个用例；本机 nginx 1.18 实测
建站/编辑/无变更/删站四类快照行为与 SHA-256 共 16 项全过。

### §5.25 反向代理响应缓存（M2 第廿五片落地）

矩阵里反向代理这一行的最后一个未交付项（§3.2 的"缓存开关"）在这一片收口：
`PUT /api/v1/sites/{name}/proxy-cache`，请求体
`{"cache":{"valid_seconds":N,"max_size_mb":N,"inactive_minutes":N}}`，
`{"cache":null}` 清除。三个数字全部必填、没有隐式默认值——"这个页面会被旧内容服务
多久"必须是操作者做过的决定：valid_seconds 1-2592000（30 天）、max_size_mb
10-102400、inactive_minutes 1-43200，越界 400 `invalid_site`；站点不存在 404
`not_found`；nginx 拒绝 422 `nginx_rejected`；Provider 没有实现
`SiteProxyCacheManager` 时 403 `capability`，理由原话"该平台的站点 Provider 没有
实现反向代理缓存"（`internal/api/sites.go:129 siteProxyCacheManager()`）。

* **启用前提是站点已有代理所有者。** 单目标或负载均衡表任一（`proxyActive()`，
  `internal/nginx/proxyupstream.go:100`）；静态站点启用被 400 拒绝，理由原话是
  "响应缓存只对反向代理站点有意义；先启用反向代理或负载均衡，再开缓存"
  （`internal/nginx/proxycache.go:277 SetProxyCache()`）。`proxy_cache` 指令只渲染在
  代理的 `location /` 里（`internal/nginx/proxy.go:176`），旁边必然有 `proxy_pass`；
  清除（null）始终允许，并删除该站点已缓存的字节（`internal/nginx/proxycache.go:265
  removeCacheDir()`）。
* **渲染的指令是固定的，调用方提交不了任何配置文本**
  （`internal/nginx/proxycache.go:100 proxyCacheLines()`）：

  ```
  proxy_cache mp_<站点>_cache;
  proxy_cache_key "$scheme|$host|$request_method|$request_uri";
  proxy_cache_methods GET HEAD;
  proxy_cache_valid 200 302 <N>s;
  proxy_cache_lock on;
  proxy_cache_bypass $http_authorization $http_cookie;
  proxy_no_cache $http_authorization $http_cookie;
  add_header X-Cache-Status $upstream_cache_status always;
  ```

  zone 名由站点名派生（`internal/nginx/proxycache.go:86 cacheZoneName()`，形如
  `mp_<站点>_cache`，keys_zone 固定 10m）；缓存键含 `$host`，同一 vhost 的多域名不
  共享条目；`X-Cache-Status` 是固定响应头，供操作者与冒烟脚本现场验证
  HIT/MISS/BYPASS。
* **缓存字节与目录。** linux 平台的 `CacheDir = rooted("/var/cache/minipanel")`
  （`internal/platform/platform_linux.go:134`，`MINI_PANEL_ROOT` 可整体重定位），
  每站点一个子目录（`internal/nginx/proxycache.go:93 cacheDirFor()`）。目录是派生的
  主机状态、不进 marker：篡改 marker 既挪不动缓存位置，也改不了清除时删哪个目录。
  **这条决策被真实 nginx 实测修正过一轮**：第一版把缓存根放在 `<DataDir>` 下，
  冒烟第一轮就失败——nginx 只创建最后一级缓存目录、不建缺失父目录，而且 worker
  （www-data）无法进入 0700 的祖先目录（面板数据目录正是 0700）。修复是
  `internal/nginx/proxycache.go:238 ensureCacheRoot()`：写非空表前把缓存根
  `MkdirAll` 为 0755，并沿祖先链只补两个执行位（0700→0711），绝不加读/写位，
  目录列表保持私有；`TestProxyCachePreparesWorkerReachableRoot` 钉住 0755/0711
  两个权限与"清缓存不删共享根"。
* **表文件与事务。** `proxy_cache_path` 只能定义在 http 上下文，这是继限流 zone 表、
  upstream 表之后的第三个"两文件"功能：面板经与 zone 表相同的 include 发现
  （`internal/nginx/proxycache.go:159 cacheTablePath()` 复用 `limitsPathIn`）写自有
  表文件 `minipanel-proxy-cache.conf`，marker 为
  `# minipanel-proxy-cache: {"kind":"proxy-cache","file_version":1}`；每次改动按当前
  站点列表整表重建（`internal/nginx/proxycache.go:183 cacheRows()`），最后一个缓存
  站点消失时删除文件；vhost 与表文件放进同一次 applyFiles 事务（写 → `nginx -t` →
  通过才 reload → 失败两文件精确回滚，`internal/nginx/proxycache.go:277
  SetProxyCache()`）；外来同名文件（marker 不合）拒绝；本机 nginx.conf 没有通配
  include 时 400 带理由拒绝；没有缓存的机器上路径不解析，unrelated 写入不受影响
  （`internal/nginx/proxycache.go:215 cacheTableFile()`）。
* **生命周期耦合。** 清除代理（`SetProxy` 空目标或 `SetProxyUpstreams` 空表）在同一
  次事务里连带清掉缓存策略与 zone 表行（`internal/nginx/proxy.go:219`、
  `internal/nginx/proxyupstream.go:264`），提交后才删缓存目录（`internal/nginx/proxy.go:247`、
  `internal/nginx/proxyupstream.go:291`）；单目标↔负载均衡交接保留缓存（两边都不为空，
  策略不被清）；删除站点连带清表行与字节（`internal/nginx/nginx.go:1058` 起，
  `internal/nginx/nginx.go:1071 removeCacheDir()`）。
* **诚实性边界。** 只缓存 GET/HEAD 的 200/302；301 有意不缓存——永久跳转改了目标后，
  旧跳转不应继续从磁盘服务。带 Authorization 或 Cookie 的请求双向绕过
  （`proxy_cache_bypass` + `proxy_no_cache`），某个访客的登录态响应不会被发给别人。
  nginx 自身规则仍然生效：带 Set-Cookie 或 private/no-store Cache-Control 的响应不会
  被缓存，面板不覆盖它们；上游的 Cache-Control / Expires 也仍优先于
  `proxy_cache_valid`。marker 里的 `proxy_cache` 会重新走一遍 `normalizeProxyCache`
  校验（`internal/nginx/nginx.go:617`），有缓存但没有代理所有者的文件不被当作面板站点。
* **验收。** `internal/nginx/proxycache_test.go` 13 个用例（校验、两文件同写与 marker
  往返、静态站点拒绝、负载均衡宿主、清代理/清缓存/删站三条清理路径、两文件回滚、
  外来表拒绝、无通配 include 拒绝、坏 marker、与 server 级功能共存、ensureCacheRoot
  权限）；`internal/api/sites_proxy_cache_test.go` 5 个用例（审计动作
  `PUT /api/v1/sites/{name}/proxy-cache`、清除与代理耦合、错误映射、能力门槛与 CSRF、
  非法 JSON）。本机 nginx 1.18 冒烟 41 项 ALL_PASS：首个 GET MISS、第二个 HIT 且后端
  命中计数不变、Cookie/Authorization 请求 BYPASS、POST 永不缓存、302 缓存而 301 始终
  MISS、TTL 过期 EXPIRED、缓存字节落盘、单↔多交接仍 HIT、三条清理路径都删表与目录、
  结束后 `nginx -t` 通过。Playwright UI 39 项 ALL_PASS，四档视口无溢出，`make check-ui`
  绿（`TestUIReachesEveryDocumentedEndpoint` 覆盖新端点）。

## §6 面板自身暴露与访问控制

### §6.1 是什么、不是什么（沿用 M0 的口径，不许漂）

访问控制只有四样：监听地址、会话令牌与有效期、IP 白名单、CSRF + 失败锁定。
**入口路径是掩护不是鉴权**，伪装响应同理；拿到有效会话就能从任意路径访问面板，这一点在
M1 的逐路径收紧完成前不改变，任何文档（含本文件）都不许把入口描述成登录后的防护。

### §6.2 与参照系的三点差异

1. **失败锁定按身份**：`ip|username` 为键 + 指数退避封顶 1h。参照系里面板登录失败锁定几乎没人
   真做：1Panel 用验证码（且该验证码曾被客户端参数绕过，公开 issue 可查），Cockpit 用
   `MaxStartups` 限并发，其余交给系统 fail2ban。宝塔的阈值是每 IP 5 次即锁（其文档与界面可见）。
   我们不采用纯按 IP 的计数，理由是这类键一旦不含身份，同一出口 IP 上一个被爆破的用户名就能把
   运维一起锁在门外——这是设计层面要回避的后果，不是对别人实现的源码断言。我们的键含用户名，
   锁定期内正确口令也拒，未知用户与错口令响应完全一致（已交付，`m0_test.go:307/481`）。
2. **凭据不发明文**：无 TLS 且监听在可路由地址 → 一律 `503 tls_required`，fail-closed。宝塔的
   登录脚本里有一条**可由攻击者主动触发**的降级分支（取不到公钥时直接明文提交），我们从不做
   客户端加密包装，因此那条分支不存在——这不是更强的加密，而是少一个失败模式。
3. **不给自己开后门**：不做免登录临时访问授权、不做免登录文件分享、不做端口隧道、不做内嵌反代。
   这四条在参照系里都存在，也都把"面板的访问控制"变成了"内部服务的访问控制"。

### §6.3 自救对称表（逐条核对，7 项全部达标；G-A/G-B/G-C 已在 M1 闭合，表体已进代码）

这张表现在是**代码里的一份数据**而不是本文的一张清单：`internal/lockout/lockout.go:52 Risks()`
按下面 7 行的顺序产出 9 行（监听/TLS 拆成"监听地址 / 端口"与"面板证书"两行，口令行之外另加
"口令待确认"——`minipanel passwd` 置的 `must_change_pw` 是实际会拦住请求的那一项）。
`docs/里程碑.md` 的 M1 一节与 `README.md` 的 CLI 一节指向同一份实现。

| 能把人关在外面的开关 | 出事方式 | 现有出路 | 判定 |
| --- | --- | --- | --- |
| 入口路径 | 改错 / 忘记 | `minipanel reset-entrance --set/--disable` | ✅ |
| 口令 | 改错 | `minipanel passwd <user>`（tty 关闭回显，作废全部会话） | ✅ |
| 监听地址 / 端口 / 面板 TLS | 端口冲突起不来、证书坏了 | `minipanel init --bind/--port/--insecure-no-tls`（写引导值前不监听任何东西） | ✅ |

| IP 白名单 | 写错一个字符 → 所有请求 403 `ip_not_allowed`，**包括修复它的那个请求** | `minipanel reset-ips --set <列表> / --clear`（`main.go:821`，只动 SQLite 设置项） | ✅ G-A |
| 口令有效期 | 可写不可执行，写了没反应（不是关在外面，是虚假安全感） | 执行点已落地：`auth.go:155 passwordExpired()` → `server.go:365 passwordGate()`，到期只放行改密与登出 | ✅ G-B |

G-A / G-B / G-C 三条原本"排在任何新页面前"，现已全部闭合。落地的形态与当初的修法一致：

```
G-A  minipanel reset-ips            [--set <cidr 列表> | --clear]   # 只动 SQLite 设置项，panel.json 无关
G-B  口令有效期执行点：到期 → passwordGate 只放行 /session、/password、/logout
G-C  minipanel reset-2fa            --clear [--user <账号>]         # 关掉 2FA 并作废该账号全部会话
     一次性恢复码：仍未做（原方案里就标为"可选加分项"）
```

同步要求现在由测试兜着，而不是一句约定：新增一条 `reset-*` 时，它要进 usage 文案
（`TestUsageCoversEveryCommand` 逐条比对 8 个子命令与 8 个 flag），要进上面这张表
（`internal/lockout/lockout.go` 加一行），而表里写的每条命令与每个 flag 又必须真的存在——
`cmd/minipanel/lockout_test.go` 拿表里的文本去 `dispatch()` 试一个不存在的 flag，
再逐条回查 usage。**方向是反的**：不是"命令改了记得改文档"，而是"表里写了一条不存在的命令就红"。
不进 `openapi` 的仍然是**命令本身**（CLI 不是 API 面）；M1 之后进规格的是这张表的**只读视图**
`GET /api/v1/lockout-risks`，它不执行任何东西，§3.10 的「CLI 对照」页渲染的就是它。

## §7 备份设计（M6，但语义现在就定）

四条被参照系证明"便宜但直接决定可信度"的规则，现在写死，避免 M6 时重新讨论：

1. **保留 N 份只计成功**。失败记录不占保留额度，否则备份目录会被失败挤满而"看起来有备份"。
2. **上传后 `存在 + 大小` 双校验**，结果写进执行报告；校验失败 = 任务失败。"你去存储桶自己看一眼"
   不是可验收的备份。
3. **恢复前先自动备份当前状态**，恢复步骤落 checkpoint，中断可从中间步续跑；`Restore` 是写操作，
   因此受 §5.2 约束。
4. **预检**：目标可达（试传）、空间 ≥ 2× 估算、时区一致；不足时给分条解法，不给一个错误码。

两条边界：
- **对象按粒度分件**（站点 / 库 / 配置 / 面板自身各成一件），恢复入口允许"只恢复一个库"。
  整包 tar 的代价在参照系里有据可查：用户想恢复一个邮箱就得动整包。
- **文档必须写清"面板备份不含什么"**（容器数据卷、非面板创建的目录、云厂商快照）。
  这句比"含什么"更能防误解。
- **面板自身状态要不要备**是必答问题：M6 包含面板 SQLite + `panel.json` + 配置历史目录，
  不含第三方云凭据的明文（凭据本身 0600 在库里，备份出去等于把凭据带走，需在预检里警告）。

## §8 不做清单

分四组。理由列只允许指向成文纪律或可核验的公开事实。

### §8.1 会破坏"自主可控"定位的

| 不做 | 理由 |
| --- | --- |
| 软件商店 / 插件安装 / 第三方应用一键部署 | 以 root 拉取并执行任意第三方代码，同时摧毁"单一二进制 / 不引入 cgo / 不做面板自更新"三条纪律；且长尾模块每一个都是攻击面（参照系：Webmin 127 个模块目录至今含 `minecraft`） |
| 面板内任意 URL 下载器、URL 访问型计划任务 | SSRF 面，可直接打内网元数据服务。参照系里同类入口有公开公告 |
| 任意参数的命令执行器（Webmin Custom Command 一类） | 官方承认导致 root 提权。需要执行就走已鉴权、可审计、可录像的终端 |
| 免登录文件分享 / 临时登录授权 / 内嵌 phpMyAdmin 反代 / 端口隧道 `/p/<port>` | 把面板端口变成第二张网，等于"面板的访问控制 = 内部服务的访问控制" |
| 面板自更新 / 在线升级 / 首页"修复"按钮 | 升级 = 换二进制；schema 只向前；回滚 = 回旧二进制。运行时自我改写使版本与审计失去意义 |
| 遥测 / 崩溃上报 / 云端账号绑定 | `/healthz` 里 `telemetry:false` 是事实陈述；验收有一条 grep 断言非测试代码无出站调用 |

### §8.2 参照系里存在但收益/成本比不成立的

| 不做 | 理由 |
| --- | --- |
| 站点级 WAF / 防篡改 / 签名扫描 / 安全评分 | 评分不可验证（参照系里同类评分给出 30/100 却无法说明"100 长什么样"）；扫描需持续签名库更新，把判断权交给外部 |
| 邮件 / DNS 权威 / FTP 托管 / 邮局 / WordPress 套件 | 均非"面板"职责：投递声誉、25 端口被普遍封、额外公网端口面，成本全在运维侧 |
| 多节点 / 跨节点文件互传 / 整机迁移 / 集群负载 | 需要保管对端 root 凭据（§9 未决）；集中管理该用 Agent 模型，不是浏览器里缝 N 台 |
| AI 网关 / 模型管理 / Benchmark / 终端里的 AI 分析 | 方向性押注，与"把这台机器管明白"无关；把操作日志与终端上下文交给第三方分析与"每次操作只在本机留痕"相反 |
| 容器管理页（生命周期 / Compose / 镜像 / `daemon.json`） | 见 §8.3 唯一保留项。接管 Docker 等于接管一台机器；且 `daemon.json` 改动可能让面板自己失联 |
| 计划任务命令黑名单 | UI 写死 `shutdown/mkfs/passwd` 是假安全感：一条 `sh -c "s""hutdown"` 就绕过，同时给用户"面板替我决定"的错觉。改为脚本进审计 + 快照 + 无提权语义 |
| 首页卡片自定义 / 主题 / logo / 终端配色 / 备忘录 | 装饰性支出；单机自用 |
| DHCP / VLAN / Wi-Fi / 访客网络 / Mesh / 流量整形 / QoS / DNS 过滤 | 路由器功能盘里 61 项中"不搬"的 14 项：服务器不给别的设备发地址，界面永远空转 |

### §8.3 看起来是"不做"、其实换了形状的（保留判断）

| 参照系做法 | 我们的替代 |
| --- | --- |
| 应用商店一键部署 | **本地静态站点模板 + Nginx 配置片段库**（值 80%，零下载、零执行第三方代码） |
| 容器管理 | **只读暴露面**：Docker `-p` 造成的监听与规则来源必须出现在 §3.1/§3.5，不出现"启停容器"按钮 |
| 配置要求"你自己去装 firewalld" | `degraded` + 一条可复制命令 + 一个 `verify` 复查链接（§4.2） |
| 免登录分享文件 | 审计导出走 CLI（`minipanel audit export`），不开下载端点 |
| 整机快照备份 | 面板状态（SQLite + `panel.json` + 配置历史）纳入 M6 备份对象，但不含第三方云凭据明文 |

### §8.4 与"未排期"的区别

`未排期` = 现在不做、但没在 §8 里被判死刑，且**代码里必须已经有对应 Deny 理由或干脆没有 key**。
不做（§8）= 明确拒绝，写理由。混淆这两者就会重新产生"菜单里有、点了是空的"。

## §11 验收增补

每条新纪律都要有一个能失败的测试，否则它只是文案。

| 设计断言 | 测试 |
| --- | --- |
| 每个 `state != available` 的 key 必须有非空 `reason` | 扩展 `capabilities_test.go`：白名单机制不变，另加"四态结构完整性"（`degraded`/`foreign` 允许 `fix_action=null`，`unavailable` 必须有 `reason`） |
| 写端点返回 `affected` 且快照已落盘 | 每个 Provider 一个用例：改 → 断言 `config-history` 下有对应字节 → 回滚 → 断言与原文件一致 |
| 回滚不产生无限快照链 | 断言深度上限生效 |
| `foreign` 对象不可写 | 构造一条非面板来源的规则/站点，PUT 必须 `403`/`409` 且原因含来源 |
| `fix_action` 不含包名/URL/命令 | 契约层校验 `fix_action.kind ∈ {panel, copy_command, verify}` 且 `copy_command` 来自静态白名单 |
| 路径参数只许 `{key,id,name}` | `contract_test.go`（A9） |
| 文件路径不进 URL | 断言 `POST /files/*` 形态不存在，只有 `/api/v1/files` + 请求体 |
| IP 白名单写错不会把人关死 | CLI 用例：写入一个排除当前 IP 的白名单 → `minipanel reset-ips --clear` → 能登录 |
| 2FA 复位出路 | CLI 用例：启用 2FA → `reset-2fa --clear` → 口令登录可用（若做恢复码，另测一次一码） |
| 备份只计成功 | 造两次失败 + 一次成功，`retention=1` 断言只剩成功那份 |
| 备份 Exist+Size 校验 | 假后端返回大小不符 → 任务状态 `failed` 且报告含校验字段 |
| 无出站网络 | 现有 grep 验收（`Makefile`/验收 #17）保持为空；新增 handler 不得引入 `net.Dial` |

## §12 与三份研究的差异（我否掉或改了什么）

1. **把 `config_history` 从 M6 拆到 M2（协议）+ M4（UI）**。研究档案建议 M6，我认为错：M4 的防火墙
   写入如果早于撤回能力上线，那么撤回能力最该在的那天恰好没有。
2. **拒绝给能力位图加第五态**。档案建议 `{available|degraded|unavailable|foreign}` 之外再加
   `pending`（"可写但未生效"）。我不加：那是缺陷不是状态，正确修法是 A2 删掉 `basic_auth`、
   §6.3 G-B 补上有效期的执行点。留着 `pending` 就等于把"有按钮无逻辑"制度化。
3. **拒绝 `fix_action` 承担装包**。档案建议学 Cockpit 的 "Enable PCP metrics collector" 一键补齐。
   这条我不照抄：我们不在运行时安装任何东西（§4.2 三类边界）。改成"给一条可复制的确切命令 +
   事后复查入口"，收益相近、纪律不破。
4. **拒绝把逐连接/监听塞进 `monitor`**。档案也建议拆开，这里一致；但我把 `listeners` 提到 M4 的
   理由换成 §1.5（暴露面是主语），不是为了图表性能。
5. **否掉远端主机/批量输入到所有连接**（1Panel 的终端有）。效率是真的，但它同时需要凭据保管、
   目标确认和"改错一批机器"的回撤能力，三者现在都没有答案 → §9 未排期。
6. **否掉计划任务的命令黑名单**（同类面板 UI 里写死 `shutdown/mkfs/passwd`）。这是假安全感，
   且与"运维本人就是管理员"的定位矛盾。
7. **否掉安全评分**，保留 `doctor` 式的一次可复查状态输出。
