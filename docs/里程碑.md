# Mini Panel 里程碑与验收标准

范围与措辞来源：能力位图的拒绝表（`internal/platform/detect.go` 与各平台实现里的
`Deny(..., "…在 Mx 交付")`）是里程碑**功能内容**的唯一依据。本文件不新增承诺：某项功能写在哪一个
里程碑，取决于它在位图里被标记成哪一句理由；要改里程碑，先改代码里的理由，再改这里。
**唯一的例外是 M5**：代码里没有任何以 "M5" 为理由的 Deny 文案（复核：
`grep -rn "M5" --include='*.go' .` 为空），M5 = "Windows 完整支持" 是项目层面的定位，
它只把已经分布在 M0/M2/M4 的 Windows 约束收敛成一个可判定的 GA 定义，不引入任何新组件。

技术决策见 `docs/技术选型与MVP规格.md`。

---

## M0 —— 面板自身（已完成）

交付内容：单二进制（API + 内嵌页面）、CLI 自救、引导配置、SQLite 运行态、身份与会话、
安全入口与伪装、TLS fail-closed、双提交 CSRF、登录锁定、TOTP、只追加审计、能力位图契约、
平台探测与交叉编译矩阵。

按能力位图的白名单口径（`internal/platform/capabilities_test.go:72`），M0 唯一算作"功能"的是
**审计日志**；上面列的其余内容是**面板自身**的机制，不是主机管理功能。站点、PHP、数据库、备份、
防火墙写入、服务启停、终端、监控、文件权限管理在位图里全部为 `false` 且带理由，接口面上也不存在
对应端点（`internal/api/openapi/panel.yaml` 里只有 `healthz`、`setup`、`login`、`logout`、
`session`、`capabilities`、`system/info`、`settings`、`settings/{key}`、`audit`、`2fa/*`、
`password` 这 13 条路径）。M0 留下的已知缺口与设计纪律集中在
`docs/技术选型与MVP规格.md` §8。

**验收标准（必须全部为真，且每条都有自动化检查或可复现命令）**

| # | 标准 | 怎么验 |
| --- | --- | --- |
| 1 | 一条命令产出可执行文件，无 cgo、无前端构建步骤 | `make build && ./bin/minipanel version` |
| 2 | 四个平台 × 两种架构全部编得过；其中 linux/amd64、linux/arm64、darwin/arm64、windows/amd64、freebsd/amd64 逐条实测，另外 `GOOS=windows\|darwin\|freebsd go vet ./internal/...` 退出码 0 | `make build-all`；跨平台 vet 见 `docs/技术选型与MVP规格.md` §6 |
| 3 | 干净树上 `go vet` 无输出、`go test ./...` 全绿、`gofmt` 不产生 diff | `make vet && make test && make fmt` |
| 4 | 路由表与 OpenAPI 规格双向一致；规格里没有反射式接口，唯一路径参数是 `settings/{key}` | `make check-contract`（`TestOpenAPIContractMatchesRoutes`、`TestSpecDeclaresTheSecurityContract`） |
| 5 | 能力位图自洽：`features=false` 必然带非空理由；**白名单只含 `audit`**，白名单外报 `true` 与白名单内报 `false` 都算失败 | `make check-honesty`（`TestDetectedCapabilitiesAreExplained`（含 `capabilities_test.go:72` 的白名单）、`TestCapabilitiesAreSelfConsistent`、`TestDenyAndAllowAreSymmetric`） |
| 6 | 面板失联时可从 SSH 自救：查看状态、重置口令、更换入口；tty 下口令输入**真的不回显**（`term.ReadPassword`），管道下不提示 | `minipanel doctor [--json]`、`minipanel passwd <user>`、`minipanel reset-entrance` |
| 7 | 无 TLS 且监听在可路由地址时，凭据接口一律拒绝（不是降级明文） | `TestCredentialsRefusedWithoutTLSThenListeningOnRoutableAddress` |
| 8 | 未登录时入口外的路径按 `unauth_status` 伪装成**中性 HTML 错误页**（不含产品名与版本；444 直接断连）；`/healthz` 仍可达；盲 POST 登录/初始化被拒；**持有合法会话后任何路径可访问**（有意为之，见 M1 待办） | `TestEntranceGateDisguisesEverythingElse` |
| 9 | 写操作没有匹配的 `X-Mini-CSRF` 就 403 | `TestMutationsRequireCSRF` |
| 10 | 达到 `login_limit` 后锁定，锁定期内正确口令也 429；换一个用户名不受同一锁影响 | `TestLoginLockoutAfterNFailures` |
| 11 | 未知用户与错误口令响应完全相同（无账号枚举） | `TestLoginGivesIdenticalAnswersForUnknownUserAndWrongPassword` |
| 12 | 审计记录写操作（含失败），口令类字段掩码，另存 `params_hash`；接口面上不存在删除端点 | `TestAuditRecordsMutationsWithMaskedSecrets`、`TestMaskCoversTheShapesCredentialsArriveIn` |
| 13 | 改密 / CLI 设口令会作废既有会话；登出后旧 Cookie 失效 | `TestLogoutAndRevokeSessions` |
| 14 | TOTP 未确认前不生效，启用后仅有口令不足够 | `TestTOTPSetupEnableAndRequiredAtLogin`、`TestTOTPVector` |
| 15 | `panel.json` 与数据库文件（含 `-wal`/`-shm`）落盘即 0600 | `TestSaveAndLoadRoundTripWithPermissions`、`TestFilePermissionsAreOwnerOnly` |
| 16 | 引导值不可经 API 修改；设置白名单逐项校验；`GET /api/v1/settings` 每项带 `source`（`db` \| `panel.json`），引导值回显**进程真实使用**的值，`panel.entrance` 永不回显路径本身（用 `minipanel doctor` 看） | `TestSettingsAllowListAndValidation` |
| 17 | 无遥测：非测试代码里不存在出站 HTTP/拨号 | `grep -rnE "http\.(Get|Post|Client|DefaultClient)|net\.Dial\(" --include='*.go' . \| grep -v _test.go` 为空，且 `TestHealthIsPublicAndHonest` 断言 `telemetry:false` |
| 18 | UI 上未交付项显示为灰 + 理由，不存在"点了没反应"的按钮 | `GET /api/v1/capabilities` 与 `webui/dist/index.html` 的 features/unavailable 分支；由第 5 条兜底 |

M0 里**明确不交付**（继续保持灰 + 理由）：站点、Nginx/Apache、PHP 与扩展、站点证书、数据库、
备份、计划任务、防火墙写入、服务启停、终端、监控、文件权限管理、SSH/RDP 管理页。

## M1 —— 账号与会话

* 账号与会话管理成为面板内的常规页面，而不是 M0 的引导路径：会话列表（IP、UA、创建/过期时间、
  撤销），支持撤销单个或全部会话。
* 口令有效期策略（`panel.password_expiry_days`）真正生效：到期强制改密，`must_change_pw` 走完整
  交互闭环。
* 前端工程化：Vue 3 + Vite + Element Plus，产物仍输出到 `webui/dist` 并被同一 `go:embed` 打进
  二进制；接口面与 M0 完全一致，因此 `make check-contract` 与既有 M0 用例不许变红。
* `mp_entrance` / `mp_csrf` / `mp_session` 三个 Cookie 的语义不变；新增页面必须继续走双提交 CSRF。
* **收紧入口边界（M0 留下的已知缺口）**：对 HTML 导航逐路径校验入口，即登录后访问
  入口之外的**页面**导航时重新检查 `mp_entrance`（API 与静态资源保持现状，深链刷新靠会话内的
  一次引导跳转解决）。M0 的现状是"有合法会话即可从任意路径访问面板"，因此
  **入口不缓解 XSS 与 Cookie 泄露**；这条收紧的目的不是增加一道鉴权，而是把"攻击者拿到会话后
  还能复用哪个 URL"这件事收回到一次导航上。做完之前，任何文档都不许把入口描述成登录后的防护。

**验收要点**：新增会话/账号端点全部登记进 `openapi/panel.yaml`（契约测试自动把关）；
能力位图不因前端换代而放宽；`make build-all` 仍然通过（前端产物入库，不引入 cgo）。

## M2 —— 站点、PHP 与站点证书

依据位图理由原文：站点创建与 Nginx 配置生成、站点写入、PHP 多版本安装、PHP 版本切换、
PHP 扩展编译安装、站点证书签发与部署（随 Nginx Provider）；Windows 侧为
"PHP 版本探测与 php-cgi 进程池管理"。

* `WebServerCtl`（`TestConfig`/`Reload`/`Restart`）与 `PHPCtl`（`Versions`/`PoolDir`/`SocketPath`）
  从声明变成实现，Linux 与 Windows 各一份，核心层仍无 `runtime.GOOS` 分支。
* 配置生成必须"先测试后生效"：`nginx -t` 之类校验不通过就不 reload，并保留可回滚的上一份配置。
* `ReloadMode` 真正参与决策：Linux `sighup`，Windows `restart_only`。
* 扩展安装按 `PHPExtInstall` 分道：Linux `package` / `source`，Windows 只允许 `prebuilt_dll`
  并校验版本 × TS/NTS × VC × 位数。
* 站点证书（ACME）落地后 `FeatSSL` 才置 `true`；面板自身的自签证书不算站点证书。
* 每一项写操作都要进审计（沿用 `auditWrites` 中间件），并给出快照/回滚路径。

**验收要点**：`site`、`site_write`、`php`、`php_version_switch`、`php_ext_source`、`ssl` 六个 feature
的 `true` 必须由**实际探测**得出（`Detect()` 现场验证），不许在 `newBase()` 里硬写 `true`；
`make check-honesty` 与 `make check-contract` 保持绿。

## M3 —— 数据库

依据位图理由原文："数据库 Provider 在 M3 交付"。

* 数据库 Provider（建库、建账号、授权、改口令、备份入口）落到 `DatabaseEngines` 声明的引擎上；
  未被实现引擎不得出现在 `database_engines` 里。
* 口令只走请求体，掩码后进审计（`params_hash` 机制不变）。
* `FeatDatabase` 由探测结果决定；探测不到服务进程/socket 时报 `false` 并附具体原因，
  而不是报成可用然后 500。

**验收要点**：`database` feature 打开的同时，所有数据库端点已登记规格；
删除数据库账号一类破坏性操作必须在审计里留下可辨认的 `params_hash`。

## M4 —— 主机管理：防火墙、服务、终端、监控、文件

依据位图理由原文：防火墙规则写入、服务启停、Web 终端与录像审计、监控采集与图表、
文件权限（属主/模式）管理随文件管理器、SSH/RDP 访问管理页；Windows 防火墙 Provider。

* `FirewallCtl` 的 `Snapshot()` / `Restore()` 是**强制**要求（见 `internal/platform/paths.go`
  接口注释）：改规则前必须能拿到可还原的快照，先装"把自己锁在门外"的保险。
  默认不得关闭面板所在端口。
* `service_write` 与 `firewall_write` 这类"能不能改"的子 feature 与只读态分开灰度。
* Web 终端走那一条预留的 WebSocket 通道；因此**不得**给 HTTP Server 加全局 `WriteTimeout`
  （`cmd/minipanel/main.go` 的注释已钉住这一点）。
* 终端必须录像并进审计；监控采集只读，不进 `auditWrites` 的写记录。
* 文件权限管理在 POSIX 上暴露属主/模式，在 Windows 上不得出现 chmod 类控件
  （`Permissions=acl`，`FeatFilePerms` 保持拒绝）。

**验收要点**：`firewall`、`firewall_write`、`service_write`、`terminal`、`monitor`、
`file_posix_perms`、`ssh_manager` 全部由探测驱动；任何一项在另一平台上不可用时，理由必须区分
**这台机器上没装** 与 **这个平台还没有写入 Provider** 两种情况——代码里已经是两句不同的原文
（`internal/platform/platform_linux.go:81` 与 `:83`，区分说明见 `:77-79` 的注释），
Windows 侧对应 `"Windows 防火墙 Provider 在 M4 交付（当前版本只读展示）"`
（`internal/platform/platform_windows.go:82`）。

## M5 —— Windows 完整支持（把分布的能力收敛成受支持的 GA）

**这一节不引入新功能。** M5 的定位是项目一开始就敲定的那条："Linux 先行，抽象层从第一天就要能
为 Windows 服务"——抽象层确实是这么写的（下表），所以 M5 要交付的不是"再补一批 Windows 代码"，
而是**把散在 M0/M2/M4 里的 Windows 部分变成有安装/升级/回滚路径、有 CI、可以对外承诺的版本**。

### 5.1 已经分布在前面里程碑里的 Windows 工作（代码为证）

| 所在里程碑 | 已存在的东西 | 位置 |
| --- | --- | --- |
| M0 | 构建标签分文件、路径、探测、能力位图：`Permissions=acl`、`ReloadMode=restart_only`、`PHPModes=[cgi]`、`PHPExtInstall=[prebuilt_dll]`、`Firewall=windows_filter_platform`、`ServiceManager=windows_scm`、`Schedulers` 追加 `taskschd`、RDP/OpenSSH、`isElevated()` 令牌判权 | `internal/platform/platform_windows.go:27-31`（路径）、`:45-101`（`Detect()`）；枚举定义 `internal/platform/capabilities.go:41`、`:54`、`:74`、`:62-64` |
| M2 | php-cgi 进程池管理 | 原文：`"PHP 版本探测与 php-cgi 进程池管理在 M2 交付"`（`platform_windows.go:73`）；重载方式按 `restart_only` 并在 M2 落地时用金丝雀用例验证（`:57-59` 注释） |
| M2 | 预编译 DLL 扩展安装（版本 × TS/NTS × VC × 位数） | 原文：`"Windows 上不支持编译 PHP 扩展，只能安装与 PHP 版本 / TS-NTS / VC 运行库 / 位数完全匹配的预编译 DLL"`（`:72`） |
| M4 | WFP 防火墙 Provider 写入 | 原文：`"Windows 防火墙 Provider 在 M4 交付（当前版本只读展示）"`（`:82`） |
| M4 | SCM 服务启停、远程访问（RDP/SSH）管理页 | 原文：`"服务启停在 M4 交付"`（`internal/platform/detect.go:76`）、`"远程访问管理页在 M4 交付"`（`platform_windows.go:99`） |
| 永久差异 | POSIX 属主/模式在 Windows 上没有对应物，不是"等到某个里程碑就修好" | 原文：`"Windows 使用 ACL 与继承，POSIX 权限位仅作只读展示"`（`:55`），且 M4 明确要求 chmod 类控件不许渲染 |

### 5.2 M5 完成定义（必须逐条为真才算 GA）

| # | 验收项 | 判据 |
| --- | --- | --- |
| 1 | **安装 / 升级 / 回滚** | 存在受支持的 Windows 安装路径（服务注册走 `windows_scm`，`:84`）；升级只换二进制，`panel.json`、`minipanel.db`（含会话、口令哈希、审计）与站点根目录保持不变；`store.go:74-75` 的"拒绝降级"在升级后仍然成立，因此回滚 = 回到**旧二进制 + 它写入时的 schema**，文档必须写清"回滚不需要改数据库，改了 schema 就不能回滚"这条后果；卸载后不留计划任务/服务/防火墙规则 |
| 2 | **全部 M2/M4 功能在 Windows CI 绿** | 站点创建与配置生成、php-cgi 池、预编译 DLL 扩展、WFP 规则写入与 `Snapshot()`/`Restore()`、SCM 服务启停、Web 终端、监控采集，在 Windows runner 上有**断言**而不是"能编过"；`make build-all` 的 4 OS × 2 arch 是前提而非结论（§6 矩阵） |
| 3 | **伪装与入口在 IIS-less 部署下可用** | 面板自己就是 web server，不挂 IIS/ARR/反向代理（`cmd/minipanel/main.go` 的包注释："There is no separate web server"），监听端口即面板端口；`unauth_status` 的中性 HTML 页与 444 断连、`mp_entrance` Cookie、TLS fail-closed 在 Windows 上与 Linux 行为一致，`TestEntranceGateDisguisesEverythingElse` 一类用例必须在 Windows runner 上跑绿 |
| 4 | **提权语义清楚** | 未提权时写操作报"这台机器不允许，因为进程令牌未提权"，而不是 500 或静默失败（`isElevated()` 在 `platform_windows.go:123-127`，判的是进程令牌）；`IsPrivileged=false` 不得被 UI 当作能力位 |
| 5 | **位图仍然诚实** | M5 之后 `internal/platform/capabilities_test.go:72` 的白名单里新增的每一项，都必须有对应的跨平台实现与 `Allow()` 调用；`SupportsSubSecondCron`（`:91-93`）仍只在面板内置调度器下为真，因为 `schtasks` 没有秒级 recurrence |

**不算 M5 的**：让 Windows 与 Linux 逐字节相同（POSIX 权限位就是没有）；把面板做成 IIS 站点或
Windows Service 之外的形态；在 Windows 上引入 cgo 或 MSVC 工具链——`CGO_ENABLED=0` 是硬要求（§6）。

## M6 —— 计划任务与备份

依据位图理由原文："计划任务调度器在 M6 交付"（`internal/platform/detect.go:69`）、
"备份任务与归档管理在 M6 交付"（`:68`）。

* 调度器：面板内置调度器（`capabilities.go:62` 的 `SchedPanel`，注释即 "always available"）与
  系统调度器（`crontab` / `taskschd`）两条路径都实现；`SupportsSubSecondCron` 只在面板内置
  调度器下为真，理由见 `platform_windows.go:91-93` 与 `platform_linux.go:102` 的注释。
* 写系统 crontab 必须是"读-改-写 + 保留他人条目"，且写入前留备份，出问题可还原。
* 备份任务：归档产物落在 `BackupRoot()`（Linux `/www/backup`，Windows `C:\wwwbackup`，
  `platform_linux.go:21` / `platform_windows.go:31`），任务本身进审计；恢复路径要有明确确认。
* 与 M3 数据库备份、M2 站点备份共用同一套归档命名与保留策略。
* **子账号（同属 M6，但尚无验收标准）**：`internal/api/server.go:391` 的注释把
  `SessionUser` 的演进标为 "M6 (sub-accounts)"——把具体用户名变成一个更完整主体里的一个字段，
  handler 不动。代码里**没有**对应的 feature 名与 Deny 理由，因此这条只能算"排进了 M6"：
  在位图里出现明确条目之前，本文件不为它写任何承诺。

**验收要点**：`cron`、`backup` 两个 feature 打开前，调度与备份的实际执行必须已在测试里被覆盖
（不允许"位图说会跑，代码里没人调用"）；任务失败要能被审计与日志同时看见。

## 每个里程碑通用的完成定义

1. `make vet` 干净，`make test` 全绿，`make fmt` 无 diff，`make build-all` 八个目标全部产出。
2. `make check-contract` 绿：新端点先进 `openapi/panel.yaml`，安全语义写进 `description`。
3. `make check-honesty` 绿：新能力打开的同时，仍关闭的项带可读理由。
4. 所有写操作进审计，口令形状的值一律掩码，`params_hash` 可对账。
5. 平台差异只出现在 `internal/platform` 的构建标签文件里。
6. `README.md` 的"当前状态"与本文件的范围表同步更新——**先改代码，再改文档，不写超前承诺**。
